## Выводы

1. **Модель записи зерна Z1 подтверждена на камере (Д).** USB D195 → индекс внутренней настройки `0x108` → функция `0x2C88E98` (ветка `0x2C8A2A8`) → два байта банка слота: 4 → (1, 1), 2 → (1, 0), 1 → только GRAIN = 2. Размер при «выключено» не трогается — это и даёт чтение 6/7. Значит, в банке слота **GRAIN_SIZE = 1 — крупное**, 0 — мелкое (в терминах кодов USB/fujicli).
2. **Расхождение с таблицей значений прошивки для `0x108` (`0x1769350`, порядок USB [5,3,4,2,1], имена Q_GRAIN HIGH_BIG/HIGH_SMALL/…) остаётся открытым.** По ней индекс 0 = (0,0) соответствует USB 5 / HIGH_BIG, а свойство слота D195 для тех же байтов даёт 3 (Strong/Small, проверено по MakerNote в опытах D185). Либо свойство съёмки D023 и свойство слота D195 кодируют размер по-разному, либо наши имена строк словаря сдвинуты. Решает проверка в меню камеры (что показывает GRAIN EFFECT у C3, где в банке 0/0).
3. **D1A5 — не настройка слота, а текущий размер снимка (Д по поведению).** Запись 18 (= 0x12, в кодировке D18E — M 4:3) изменила текущие PIXEL (L→M) и ASPECT (3:2→4:3); запись 7 (L 3:2) вернула. Поэтому D1A5 = 7 «во всех слотах»: выбор слота на него не влияет. Прежняя гипотеза координатора «JPEG/HEIF» опровергнута.
4. Камера возвращена в исходное состояние: копии после шагов 3 и 5 совпадают с исходной байт в байт; D18C = 1.

## Проверка в меню камеры (владелец, 18.11.2026)

MENU → настройки качества → изменить/сохранить пользовательскую настройку → C3 → эффект зерна: **STRONG SMALL**. В банке C3 = GRAIN 0, SIZE 0; по USB D195 = 3.
Итог (**Д**, три независимых источника — банк, USB, меню): GRAIN 0 = Strong, 1 = Weak, 2 = Off; GRAIN_SIZE 0 = Small, 1 = Large. Свойство слота D195 кодирует честно.
Открыто (**Г**): подписи строк словаря Q_GRAIN для свойства съёмки D023 (меню 0 → USB 5 «HIGH_BIG» …) и таблица `0x1769350` для `0x108` не согласуются с этим порядком — либо D023 кодирует размер иначе, либо строки словаря сопоставлены со сдвигом. Проверяется чтением D023 в режиме съёмки по проводу при известном зерне.
