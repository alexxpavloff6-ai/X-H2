# Итог: как прошивка X-H2 5.30 обрабатывает настройки слотов по USB (18.11.2026)

Координатор — Claude Opus 5.5, исполнители — Codex gpt-6-luna (xhigh): Z1 зерно, Z2 карта свойств слота, Z3 правила сочетаний. Опыт на камере и проверка в меню — с разрешения владельца, камера возвращена в исходное состояние (резервная копия совпала байт в байт).

## Главное

1. **Цепочка «USB → прошивка → банк» для зерна прослежена полностью по записи (Д).** USB-свойство слота `D195` (группа слотов `0x3443590`) → индекс 0–4 объединённой внутренней настройки `0x108` → общий сеттер `0x2C88E98` (таблица переходов `0x33A77E8`, ветка `0x2C8A2A8`) → два байта банка слота `UI_SETP_GRAIN` (0x106) и `UI_SETP_GRAIN_SIZE` (0x107). Индекс 4 («выключено») пишет только GRAIN = 2, размер не трогается. Проверено эмуляцией всех пяти ветвей (Z1) и записью 4 / 2 / 1 на камере.
2. **Кодировка зерна в банке (Д, банк + USB + меню камеры):** GRAIN 0 Strong, 1 Weak, 2 Off; SIZE 0 Small, 1 Large. Чтение D195: `Off → 6 + SIZE`, иначе `3 + 2·SIZE − GRAIN`. Поэтому 6/7 — «выключено, помню мелкое/крупное».
3. **Открыто:** где именно собираются коды 6/7 при чтении и где запись 6/7 отвергается с 0x201C (функция чтения `0x108` — `0x2C94A78` — отдаёт только 0–4, значит, 6/7 добавляет слой USB-свойств слота). Таблица значений `0x1769350` и наш словарь Q_GRAIN для свойства съёмки `D023` не согласуются с подтверждённым порядком — **Г**, проверяется чтением D023.
4. **D1A5 — текущий размер снимка, не настройка слота (Д по поведению).** Запись 18 (= M 4:3 в кодировке D18E) изменила текущие `UI_SETP_PIXEL`/`UI_SETP_ASPECT`; запись 7 (L 3:2) вернула. Гипотеза «JPEG/HEIF» опровергнута опытом.
5. **Карта свойств слота D18C–D1A5** (Z2): 26 свойств; D18C = `UI_SETP_CUSTOM_SET_SAVE`, D18D = `CUSTOM_SAVE_NAME` (Д), D195 = GRAIN + GRAIN_SIZE (Д), остальные сопоставлены с UI_SETP по смыслу (К): D18F QUALITY, D190 DRANGE, D191 WIDEDRANGE, D192 FILM_SIM, D193/D194 BLACK_TONE/_RG, D196 SHADOWING (Color Chrome), D197 BLUE_EFFECT, D198 SMOOTH_SKIN, D199 WB, D19A/B WB_TUNING_R/B, D19C WB_KELVIN, D19D/E HIGHLIGHT/SHADOW, D19F STILLCOLOR, D1A0 SHARPNESS, D1A1 NR, D1A2 CLARITY, D1A3 LEQ, D1A4 COLOR_SPACE.
6. **Правило «ч/б тонировка только для Monochrome и Acros» найдено в коде (Д).** `0x2CA0644`: оценщик состояния `0x2C9B038` для `BLACK_TONE` (0x6A2) читает `FILM_SIM` (0x68E) через `0x2C93FD4` и `0x1135930` и разрешает только внутренние коды 7–10 (Monochrome + фильтры) и 14–17 (Acros + фильтры); сепия (5) исключена. Так же для видео (`BLACK_TONE_MOVIE` ↔ `FILM_SIM_MOVIE`). Совпадает с правилом fujicli. Правила Kelvin ↔ WB, DR priority ↔ DR/тона, размер ↔ RAW в этом оценщике не найдены (Z3).
7. **Проявка RAW (Z3, Д по коду / К по смыслу):** при сборке параметров `0x2C93FD4` поле DR (`0x22A3568`) = `0x641` или −1 (Auto) подменяется на 100 — это и есть «Auto DR не выше исходного».
8. **Контрольный байт резервной копии `0xE4` ведёт себя как сумма байтов (К):** при записи 4 (GRAIN −1, SIZE +1) он не изменился, при записи 2 (SIZE −1) уменьшился на 1.

## Что это даёт для доработок

- Первый полностью прослеженный путь «USB-свойство → внутренняя настройка → сеттер → байты банка» — шаблон для остальных 20 свойств рецепта: общий сеттер `0x2C88E98` с таблицей `0x33A77E8` (id − 0xB) обслуживает внутренние UI_SETP, значит, искать остальные ветки нужно в той же таблице.
- Оценщик доступности `0x2C9B038` — место, где прошивка решает, «действует ли настройка»; для изменения набора плёнок или правил менять нужно его ветки, а не USB-коды.
- Для своих инструментов: зерно писать только 1–5; «выключено» сохраняет размер; D1A5 — не трогать как настройку слота, это текущий размер снимка.

## Поправка 18.11.2026 (четвёртый круг): расхождение с таблицей зерна решено (Д)

Свойство съёмки D023 при Strong Large = 5 — перевод верный. Ветка `0x2C8A2A8` передаёт веткам 0x106/0x107 номера строк меню; таблица размера `0x107` (`0x175C6D0`) хранит строку 0 как байт 1 (крупное), строку 1 как байт 0 (мелкое). Подробно — `Записи_2026-11-18/опыт_зерно/итог_опыта.md`.
