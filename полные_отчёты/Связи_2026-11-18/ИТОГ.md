# Итог: что прошивка делает с настройками дальше (18.11.2026, третий круг)

Координатор — Claude Opus 5.5; исполнители Codex gpt-6-luna (xhigh): T1 фактический слой, T2 путь AF, T3 USB-слой (по 2–3 захода). Координатор нашёл шину сообщений `0x12E863C`, писателей съёмочной структуры, поправил адресную ошибку T3 (`add #0x10, lsl #12` = +0x10000, кодировка `0x91404000`) и перепроверил таблицу зерна. Камера не использовалась.

## Главное

1. **Путь USB-записи свойства восстановлен (Д, T3 + координатор).** Код свойства запроса — `[0x26C0DF4]`; диспетчер `0x2C13E4C` (таблица ветвлений по коду) → обработчик свойства (D195 `0x2C0B970`, D18E `0x2C0BD78`, D199 `0x2C0B9F0`) → значение из PTP-буфера (`0x1320800`, указатель `0x25D99E0`) → проверка по таблице `0x1BD5AB8 + 8·id` (`0x2C0B844`) → перевод `0x1135930` → обёртка `0x2BDFBA4` → **шина сообщений интерфейса `0x12E863C(событие 0xF8, id, значение, 0xF001, 0)`**, которая пишет пять слов в `0x26B7980` → приёмник `0x2A49BC0` копирует их в «предыдущее сообщение» `0x26B7994` и вызывает общий сеттер `0x2C88E98(id, значение)`.
2. **Все три отказа камеры объяснены одной проверкой (Д по коду, К для кода ответа).** D195 = 6 — нет в таблице `0x108`; D199 = 0 — нет в таблице WB `0x5F5`; D18E в RAW-слоте — нет разрешённой строки в таблице размеров `0x18BBCF0` (учитывается флаг строки). Во всех трёх случаях вызывается `0x2C05748(0x80000080)`; перевод в PTP-ответ 0x201C не прослежен.
3. **Шина `0x12E863C` — общая для интерфейса** (≈1180 вызовов в блоке 1 с разными событиями). Это единая точка, через которую меню, USB и другие источники меняют настройки.
4. **Зерно: таблица `0x1769350` для `0x108` по строкам 0–4 → USB 5, 3, 4, 2, 1 (имена Q_GRAIN HIGH_BIG … OFF).** Опыт на камере (USB 4 → байты 1/1, USB 2 → 1/0, меню C3 = Strong Small при 0/0) требует, чтобы между строкой таблицы и веткой записи `0x2C8A2A8` размер переворачивался (строка 0↔1, 2↔3). Место переворота не найдено (кандидат — `0x2C0B844`); альтернатива — свойство съёмки `D023` показывает размер зерна наоборот. **Г**, проверяется чтением D023 при известном зерне.
5. **Фактический затвор и выдержка (T1).** Синхронизатор `0x2BD5114` переносит поля съёмочной структуры `[*0x3BCAB48 + 0x3478] + 0x19AC` (затвор) и `+0x1994` (выдержка) в выходные `0xAB8`/`0xAAB`. Писатели `+0x19AC`: `0x2DA3F60`, `0x2DB269C` (обработчик события `0x2DB2248`), `0x2DB3C9C`, `0x2DBBDC8`, `0x2DB740C`, `0x2E8C640`. В пути `0x2DB269C` нормализатор `0x14F5104` превращает 2 (MS+ES) в 1 (ES) без учёта выдержки (Д эмуляцией функции). Фактическую выдержку считает `0x14E75C0` (кэш `0x24581D0`, диапазонные проверки и табличные поправки `0x14EFC40`). Префикс `DOTLCD` у выходных полей — вероятно, верхний дисплей. **Опыт на камере (MS+ES, 1/1000, CH, CONTINUOUS, `опыт_камера/итог_опыта.md`): фактический затвор = MS (0), флаг LCD = 0 (при ES был бы 1) — Д.** Камера выбирает затвор MS+ES по выдержке; `0x14F5104` — лишь ветка события, не правило выбора. Порог MS → ES: 1/8000 — MS, 1/10000 — ES (опыт, Д).
6. **Путь настроек AF (T2) упирается в границу.** Распознавание объектов выключает распознавание лиц прямо в сеттере (Д). Смена AF-C Set → обёртки `0x1338C70/9C/CC8` → обработчики `0x12F0BD4/0x12F0C6C/0x12F0D04` → поля последнего значения `0x2680474/478/47C` и журнал сообщений `0x133CACC → 0x133C73C`; эти поля читают только ветки общего геттера `0x2C99EE4…` (проверил координатор). Через таблицы условий и сервис записей (`0x14CF124`, чтение `0x14CF354`, RPC `0x14CF45C → 0x4A458`) настройки AF не идут. Потребитель автофокуса — вне блоков 0–2 (Г: сервисный модуль/иной процессор). Поправка T2: `0x14C6384` — переход, не функция чтения записи; чтение записи `0x4C` — `0x31053F8 → 0x14CF354`.

## Что это даёт для доработок

- Добавить или разрешить значение USB-свойства (например, запись зерна 6/7) — значит поправить таблицу `0x1BD5AB8 + 8·id` или ветку проверки в обработчике `0x2C0B844`; переводить его в настройку будет та же шина `0x12E863C`.
- Шина сообщений — удобная точка наблюдения: перехват `0x12E863C` в эмуляторе/на камере покажет все изменения настроек от всех источников.
- Логика «MS+ES → фактический затвор» и вычисление фактической выдержки локализованы (`0x14F5104`, `0x2DB2248`, `0x14E75C0`); их уточнение требует опыта на камере.
