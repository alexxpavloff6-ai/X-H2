# Итог: что даёт fujicli для понимания прошивки X-H2 (18.11.2026)

Исследован открытый проект [karaolidis/fujicli](https://github.com/karaolidis/fujicli) (Rust, AGPL-3.0, ревизия `27d3a6b`, 112 коммитов с 12.10.2025 по 17.11.2026). Это программа для управления камерами Fujifilm по USB: рецепты, резервные копии настроек, проявка RAW в камере. Координатор — Claude Opus 5.5, исполнители — три воркера Codex (gpt-6-luna, xhigh). Клон только читался: fujicli не собирали и не запускали, камеру не подключали. Ключевые утверждения воркеров координатор перепроверил по исходникам и нашим сырым данным.

Отчёты исполнителей:
- [C1_протокол/отчёт.md](C1_протокол/отчёт.md): команды USB, свойства, сеанс, резервная копия, проявка;
- [C2_модель_камеры/отчёт.md](C2_модель_камеры/отчёт.md): язык описания камер FML, 29 настроек и правила совместимости;
- [C3_история/отчёт.md](C3_история/отчёт.md): история проекта и находки из исправлений.

## Главное простыми словами

1. **fujicli описывает «внешнюю сторону» камеры**: какие команды она понимает по USB, какие коды у настроек, какие значения допустимы и какие сочетания она отвергает. Устройство прошивки внутри он не описывает. Для нашей цели это словарь входов и выходов: он подсказывает, где у прошивки вход и что на нём ждать.
2. **X-H2 в fujicli только распознаётся.** USB-идентификатор `04CB:02F2` совпадает с нашим. Функции резервной копии, рецептов и проявки для X-H2 не включены (`fml/camera.cue:307–314`, `man/fujicli.7:68–71`). Полностью работает только X-T5 (тот же процессор X-Processor 5 и тот же сенсор X-Trans 5 HR). **Д**
3. **Резервную копию fujicli считает «чёрным ящиком»**: скачивает объект №0 и загружает файл обратно целиком. Сигнатуру, контрольную сумму и поля он не проверяет (`crates/fujicore/src/features/backup/manager.rs`). Наша карта банка `0x12768` с преобразованиями и контрольной суммой глубже всего, что есть у сообщества. **Д**
4. **Нашлась ошибка в нашей нумерации профиля проявки D185, исправлено.** Мы считали, что у X-H2 есть «лишнее поле 0» по смещению 509 и что все номера сдвинуты на единицу относительно rawji. По коду fujicli (`features/render/profile.rs`) и нашим сырым байтам: заголовок — это 2 байта счётчика плюс область кода профиля длиной `0x1FF`, итого 513 байт. Первое настоящее поле (`ShootingCondition = 2`) лежит ровно по смещению 513. «Поле 0» — последние четыре байта служебной области, поэтому там всегда ноль. **Д**
5. **В D185 X-H2 28 полей, а не 29.** 625 − 513 = 112 байт, то есть 28 значений. Счётчик в заголовке при этом говорит 29. По схеме fujicli отсутствует последнее поле `portrait_enhancer`, а наше «Reserved = 2» в конце — это `teleconverter = Off` (в fujicli `Off = 0x02`). **Д** по байтам, **К** по смыслу последнего поля.
6. **Коды настроек USB (`0xD18C…0xD1A4`) и номера `UI_SETP` — разные пространства.** fujicli подтверждает таблицу USB-кодов и даёт к ней значения и шкалы. Связь с внутренними `UI_SETP` и обработчиками есть только в нашем разборе прошивки. **Д**
7. **Правила совместимости fujicli — проверенное знание о поведении камеры.** Примеры: монохромная тонировка действует только с чёрно-белыми плёнками; Kelvin работает только при WB = Kelvin (`0x8007`); «Grain Off» приходит кодами `0x01/0x06/0x07`, и 06/07 запоминают прежний размер зерна; при Auto DR камера оставляет DR исходного кадра; RAW не имеет «размера JPEG»; sRGB = `0x01`, AdobeRGB = `0x02`. Всё это проверено на X-T5. Для X-H2 нужна отдельная проверка, но совпадения с нашими опытами D185 (WB, зерно, цветовое пространство) уже есть. **Д** для X-T5, **К** для X-H2.
8. **Затвора, выдержки и серийной съёмки в fujicli нет вообще.** А именно эти входы решают судьбу LCD-флага в таблице `0x3456B20`. Здесь наше исследование не пересекается с сообществом, наши результаты уникальны.

## Проверка совместимости X-H2 (18.11.2026, на камере)

Подробно: [совместимость/итог_офлайн.md](совместимость/итог_офлайн.md), [совместимость/итог_камера.md](совместимость/итог_камера.md).

- **Офлайн:** все 168 значений слотов C1–C7 X-H2 расшифрованы таблицами fujicli и уложились в пределы X-T5. Попутно расшифрованы наши прежние «неизвестные»: `D195` 6/7 = Grain Off, `D1A4` = цветовое пространство, `D18F` 1 = RAW / 4 = FINE+RAW. Лишнее свойство X-H2: `D1A5` = 7 (Г: тип файла). **Д**
- **Проявка в формате fujicli работает:** профиль на 629 байт принят, камера отбрасывает 29-е поле. JPEG совпал с родным по яркости, поправка экспозиции на позиции fujicli 4 дала ожидаемое осветление. Нумерация без сдвига подтверждена на камере. **Д**
- **Рецепт в формате fujicli работает:** в слот C7 записаны 20 свойств по правилам и в порядке fujicli, 19 приняты сразу. Отказ был только на «сыром» коде зерна `0x06`; fujicli пишет `0x01`, и его камера приняла, сохранив внутреннее «выкл + размер». Резервная копия до и после совпала байт в байт. **Д**

## Что это даёт для будущих доработок прошивки

- **Карта входов.** Для каждой настройки рецепта есть цепочка «USB-код → значение на проводе → (наш разбор) обработчик → `UI_SETP` → поле банка настроек → поле D185 → массив проявки `0x22a3550`». fujicli закрывает два первых звена с проверкой на реальной камере, наш разбор — остальные. Это готовый каркас таблицы «что за что отвечает».
- **Профиль D185 теперь раскладывается однозначно**: 513 байт заголовка, затем поля в порядке `fml/profile.cue`. Номер поля X-H2 совпадает с номером fujicli и rawji, без сдвига.
- **Правила совместимости** — образец того, что внутри прошивки должна делать проверка настроек. Если искать в коде, где камера отвергает или подменяет сочетания, начинать стоит с этих правил: монохром ↔ плёнка, Kelvin ↔ WB, Auto DR ↔ DR кадра.
- **Чего не делать:** не загружать в камеру резервную копию по методу fujicli для экспериментов. Он ничего не проверяет, а у X-H2 в fujicli даже не включена эта функция.

## Поправки к нашим материалам

- `PTP_чтение_2026-11-10/профиль_D185/ИТОГ_поля_D185.txt`: в конец файла дописано примечание о «поле 0» и поле 28. Таблица наблюдений не менялась. Чтобы перейти к нумерации fujicli, вычтите 1 из нашего номера. Поле 0 нужно исключить: это служебная область, не настройка.
- Отчёты C1/C2 повторяли нашу старую трактовку («дополнительное нулевое поле, сдвиг на один»). Правильная трактовка — пункт 4 выше.

## Запуск настоящего fujicli на X-H2 и отчёт автору (18.11.2026)

Официальная сборка `fujicli.exe` 0.4.0 (release `27d3a6b`, Windows, WPD), логи — `запуск_fujicli/`, текст отчёта — `запуск_fujicli/issue/issue_body.md`.

- Без эмуляции: `device list`, `device info`, `device reverse info` (D184 `FF179501,FA179501`, D186/D187 `X-H2_0200`), `device reverse backup export` — работают. **Д**
- С `--emulate 04cb:02fc` (X-T5): `backup export` (файл идентичен нашему по SHA-256), `simulation list/get c1..c7` (совпало с нашей расшифровкой), `simulation set c7` с тем же именем (20 записей приняты, слот и банк не изменились), `image render` черновик 3888×2592 и полный 7728×5152, `--slot c5` (MakerNote подтвердил рецепт). `--slot c7` отклонён правилом fujicli «DR рецепта больше DR кадра» — ожидаемо. **Д**
- Резервная копия до и после всех запусков совпала байт в байт; слот для USB возвращён на C1.
- Отчёт опубликован автору: https://github.com/karaolidis/fujicli/issues/7
