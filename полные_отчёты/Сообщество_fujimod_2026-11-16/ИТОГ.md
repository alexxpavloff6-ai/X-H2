# Итог: сверка с открытым проектом сообщества fujimod (16 ноября 2026)

Репозиторий: [justjake/fujimod](https://github.com/justjake/fujimod), GPL-2.0, ревизия `c61fa145` (15.11.2026), ~2650 коммитов с 16.10.2026.
Оркестрация: координатор Claude Opus (high), четыре воркера DeepSeek Harness (DeepSeek-V4.1-Flash, high) — W1 каталог, W2 эмулятор XP5, W3 USB/формат/моды, W4 коммиты.
Репозиторий и наши DAT только читались; код fujimod не запускался. Ключевые утверждения воркеров сверены координатором.
Уровни: Д — доказано/проверено, К — сильный кандидат, Г — гипотеза.

## Главное

1. **Это те же прошивки.** SHA-256 файлов в их каталоге = наши (X-H2 5.30, X-H2S 7.30, X-T5 4.31, X100VI 1.31); их декодер даёт наши блоки побайтово. **Д.**
2. **Новых версий 5.33/7.31/4.32 у них нет** — наш разбор исправлений уникален. **Д.**
3. **id свойства камеры = номер `UI_SETP`.** Объединяет нашу систему свойств, словарь USB и опровержение по `0x2B9`. `0x2B9=697=NETMASK…1OCTET_8`, `0x5BA=PERFORMANCE`, `0x6B3=STILLCOLOR`. **Д.**
4. **MOVDC — аппаратный блок X-Processor 5** (каналы `0xFF970000/1000/2000`, IRQ 171–173, рег. `+0xD8=0x10030001`, stride `+0xD0`): выходной DMA packed YUV 4:2:2. Наш `2×640=1280` — шаг строки кадра 640×480. Связь LCD-исправления с аппаратным выводом — **К** (была Г).
5. **XP5 = 4×Cortex-A53 + 1×Cortex-M4**, mailbox `0xFF90E100`, две ОS (ThreadX + Linux с `0x40000000`). Объясняет, почему флаг MOVDC и задание `[0x4daa6e8]` приходят «извне» блоков 0–2. **Д** (состав), **К** (источник).
6. **`0x979 = UI_SETP_PLAY_RESIZE`** — подтверждает, что путь события `0x358` к режиму съёмки не относится. **Д.**
7. **Перепрошивка:** статус «нельзя переписать» — **открыт**. Их моды не пишут флеш: dual boot = загрузка с SD-карты, образ из официального DAT; публичный USB — отладочный (RAM, консоль, restart, бэкап флеша), без записи флеша. Приёма изменённого DAT на XP5 в релизах нет. **Не опровергнут.**

## Чего у сообщества нет (наши результаты уникальны)

Исправления 5.33/7.31/4.32; кольцо H.265 и «минута»; CSDROB/уровень чёрного; enum `MODE_RECORD` и `[ctx+0x3978]`; Boost/Performance (замеры D304); алгоритм AF и тайминги; таблица ID объективов (`0x411` отсутствует; X-mount у них — SPI/4-байтовые пакеты без таблицы ID→модель). Эмулятор XP5 не доходит до режима съёмки/меню; AF не моделируется.

## Куда двигаться (детали — в общем отчёте «Сверка с … fujimod»)

1. MOVDC — *итог:* программирования железа MOVDC в разобранном коде (блоки 0–3, обе версии) **нет** (0 ADRP на `0xFF97x000`, 0 литералов `0x10030001`, 0 записей по `+0xD0/+0xD8`). Таблица карты регистров `0x385E14C` — статические данные, кодом не читаются. «MOVDC = packed422 DMA, stride +0xD0» — модель эмулятора fujimod, не прослежена в нашем коде. Наш патч меняет только программный дескриптор; программатор железа — вне разобранных блоков (Linux/boot ROM). Связь с LCD-линиями — **К**, не Д.
   *Образ companion-ядра M4 найден и разобран (воркеры G1/G2):* DAT `0x1C0274` (flash `0x1C0000`, ≈203 КБ, ThreadX, Thumb, SRAM `0xFA200000`); MOVDC/флаг/задание НЕ трогает — исключён.
   *Флаг = сохранённая запись `0x4C`, поле `+0x74`* (геттер `0x14C6384`; id-пространство ≠ UI_SETP), живёт за сервисным RPC (диспетчер `0x4A458`, блок 2) — писателя и условия статически нет.
   *Пункт 2 (блок 3 + сквозной скан, воркер H):* **три звена в файле обновления отсутствуют (Д)** — 0 литералов `0xFF970000`/`0xFF90E100`/`0x4c2ff14`/`0x4daa6e8` во всех 110 МБ. Блок 3 — данные (не код); Linux в сырой области = узел WiFi (Socionext MARBLE, `0x3c40274`), без MOVDC; есть шифрованный блок 1.53 МБ `0x2300274`. Программатор MOVDC/писатель флага — в boot ROM / ISP-SCM / шифрованном блоке, вне файла обновления. Закрытие требует дампа ROM или трассы на камере.
2. Проверить companion-ядро M4 и mailbox `0xFF90E100` как источник флага MOVDC и задания `[0x4daa6e8]`.
3. Брать их каталог (control-ids/settings/state/flash/restart для X-H2S, X-T5) как справочник; силы — на то, чего у них нет.
4. Подписать property_id в наших блоках 0–2 их словарём `UI_SETP` (3435 имён).

Отчёты воркеров: `W1_каталог/отчёт.md`, `W2_эмулятор_XP5/отчёт.md`, `W3_USB_формат_моды/отчёт.md`, `W4_коммиты_направления/отчёт.md` (+ `сопоставление.json` и сверочные скрипты в каждой папке).

## Замечание о назначении

Эта работа — для понимания того, **как устроена и работает** прошивка. Детали обхода проверок обновления/подписи на реальной камере здесь намеренно не фиксируются и не воспроизводятся из fujimod.
