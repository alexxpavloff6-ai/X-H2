# Связь USB-исследований с прошивкой 5.30

Проверка от 10 ноября 2026 года. Исследован FWUP0028.DAT: побитовая инверсия и распаковка четырёх блоков FFLZ тем же способом, что и в [описании прошивки](../Описание_прошивки_X-H2_5.30.md). Камера в этой части не использовалась, файл прошивки только читался.

Адреса даны как смещения внутри распакованного блока II (FFLZ с 0x840274). Блок загружается по адресу 0x029AE000, так что абсолютный адрес получается сложением, например 0x900BA0 + 0x029AE000 = 0x032AEBA0. Этот базовый адрес уже использовался в [исследовании производительности](../Исследование_без_камеры/Производительность/Отчёт.md) и совпадает со ссылками ADRP/ADD, найденными здесь.

## Главный вывод

То, что камера отдаёт по USB, не отдельная «надстройка». Это данные и код из той же прошивки, которую мы раньше разбирали без камеры. В образе найдены:

1. оба списка свойств, байт в байт как в камере;
2. таблица описаний всех 278 свойств с внутренними номерами настроек, причём у 167 из них есть имя настройки из меню прошивки (UI_SETP_…);
3. функции, которые проверяют, разрешено ли свойство в текущем режиме USB;
4. код свойства Boost, который работает с той же внутренней настройкой, что и ветка Performance в прежнем анализе.

## 1. Списки свойств

| Смещение | Длина | Что это | Совпадение с камерой |
|-|-|-|-|
| 0x900BA0 и копия 0x900E50 | 278 кодов | съёмка по проводу и обычный MTP | 278 свойств, тот же порядок |
| 0x900DD0 и копия 0x901080 | 61 код | режим «USB RAW CONV./BACKUP RESTORE» | 61 свойство |

Каждый список заканчивается 0xFFFF. Список из 61 кода содержит поля слотов D18E–D1A5, профиль D185 и D183 (размер проявки). В списке из 278 кодов их нет. Поэтому в режиме съёмки по проводу слоты не читались: дело не в ошибке, прошивка их там просто не обслуживает.

Рядом, по смещениям 0xA030E8 и 0xA03508, лежат списки операций PTP для разных режимов. В них есть 0x900C и 0x900D, то есть та пара команд, которой наш скрипт загружает RAF для проявки. Там же строка «fujifilm.co.jp: 1.0;» из ответа камеры о себе и имя загружаемого файла «\FUP_FILE.dat».

Проверочные функции:
- 0x244EC0 сравнивает запрошенный код (глобальная 16-разрядная ячейка) со списком из 278 кодов;
- 0x2451A0 делает то же для списка из 61 кода;
- 0x2451FC выбирает между ними по режиму USB и возвращает отказ 0x80000040 или 0x80000080. Это внутренняя причина ответа «свойство не поддерживается», который мы видели при неправильном режиме.

## 2. Таблица описаний свойств

По смещению 0x908A98 лежат 278 записей по 76 байт, в том же порядке, что и список. Шаг 0x4C прямо используется в коде проверки (`madd x0, x0, #0x4C`). Поля записи совпадают со стандартом PTP DevicePropDesc:

| Смещение в записи | Значение |
|-|-|
| +0x00 | код свойства |
| +0x04 | тип: 3 INT16, 4 UINT16, 6 UINT32, 0xFFFF строка (коды PTP) |
| +0x08 | доступ: 0 только чтение, 1 чтение и запись |
| +0x0C | форма: 1 диапазон, 2 список (коды PTP) |
| +0x14 | значение по умолчанию текстом, например «0x8001» или «0/-40/40/10» |
| +0x48 | внутренний номер настройки камеры, у служебных свойств 0 |

### Внутренний номер — это номер настройки меню

В блоке I лежит таблица имён UI_SETP_…: 3 465 имён подряд, начиная с UI_SETP_NONE. Внутренний номер из записи свойства совпадает с порядковым номером имени в этой таблице. Проверено по двум независимым якорям из прежних работ:
- 0x5BA = UI_SETP_PERFORMANCE: это число найдено в коде экрана производительности в [исследовании без камеры](../Исследование_без_камеры/Производительность/Отчёт.md);
- 0x6B3 = UI_SETP_STILLCOLOR: это ID параметра «Цвет», с которым исполнялся конвертер в [работе по MakerNote](../Последовательное_исследование/Этап_1/Цвет_в_MakerNote/Отчёт.md).

## 3. Boost: от USB к коду

В блоке II по смещениям 0x2FB664 и 0x2FB838 код сравнивает запрошенное свойство с 0xD304. В обеих ветках он вызывает функцию получения настройки с номером 0x5BA, рядом есть обращение к 0x5BC. По таблице имён это пять соседних настроек: 0x5BA UI_SETP_PERFORMANCE, 0x5BB _AC, 0x5BC _LEVER, 0x5BD _MODE и 0x5BE UI_SETP_FUNC_PERFORMANCE. Прежний анализ называл ровно этот диапазон, 1466…1470. Получается, что свойство D304 описано как FUNC_PERFORMANCE, а код при запросе D304 читает PERFORMANCE и PERFORMANCE_LEVER. Вероятно, LEVER отвечает за положение переключателя на корпусе, а AC за питание от сети. По коду это пока не проверено.

Выходит, что замер скорости AF (медиана Boost 172 мс против 216 мс у Normal, разница не доказана статистически) — это действие той самой ветки Performance, которую раньше видели только в коде. Значения по USB (1 и 5) и значения словаря прошивки (NORMAL 0, BOOST 2) — разные представления одной настройки, как и с плёнками.

## 4. Слоты C1–C7 и проявка

- Поля слотов D18E–D1A5 есть только в списке из 61 кода. Описаний в формате таблицы из раздела 2 для них нет, значит, их обслуживает отдельный код режима RAW CONV.
- В служебной таблице кодов по смещению 0xA94F48 поля слотов идут тремя группами: D18E–D197 (плёнка, зерно, качество и т. п.), D198–D19A (баланс белого) и D19C–D1A4 (тона, цвет, резкость, шумоподавление). Это совпадает со смыслом полей, который мы установили опытами.
- По предварительной проверке, профиль D185 обслуживается функцией, которая вызывает построитель записи 0x12E863C из исследования производительности. Это ещё нужно перепроверить. Где собираются 29 полей профиля, в коде пока не найдено: порядок полей известен только из опытов.

## Чего эта связь не даёт

- Алгоритма автофокуса: по USB видны только настройки и статус, а не данные датчиков.
- Доказательства, что настройка UI_SETP_PERFORMANCE управляет скоростью привода, а не, например, частотой видоискателя.
- Безопасности записи D171 и D208. Объявленный доступ «чтение и запись» не значит, что запись безвредна. Без отдельного разрешения владельца такие опыты не проводятся.
