# Подготовка параметров детализации: отдельный путь четырёх прошивок

## Результат и граница

Найден и на собственных ARM64-инструкциях каждой из четырёх моделей локально исполнен **другой преобразователь тех же входных смещений**, что использовались ранее писателями Sharpness, NoiseReduction и Clarity в MakerNote. Он записывает три 32-битных числа в отдельный упакованный выходной объект; это не значения тегов. На проверенных искусственных входах отображения во всех четырёх моделях совпадают. Непосредственный потребитель этого объекта и связь с обработчиком изображения **не установлены**: называть выходы коэффициентами ISP, переданными в реальную камеру, нельзя. Разрыв от объекта до обработчика изображения остаётся открытым. Аналогично названия полей основаны на совпадении конкретных входных смещений с [предыдущим исследованием MakerNote](../../Последовательное_исследование/Этап_3/Детали_и_шум/Отчёт.md), а не на доказанном прохождении UI → ISP.

[Исследование фактических проявок](../../Проявка_0296_серия_2/Итог.md) независимо показало изменения локальных показателей X-H2 для 0308/0309/0310 относительно 0300 на одной сцене. Оно не устанавливает, что найденный здесь объект участвовал в этих проявках. Предыдущий [этап 5](../../Последовательное_исследование/Этап_5/Итог.md) также не устанавливает эту связь. Никаких пикселей, работы матрицы или ISP здесь не эмулировалось.

## Точные адреса

Адреса — виртуальные адреса распакованных блоков. Начало и конец — точки отдельных запусков; конец не исполняется. Регистр `x20` искусственно указывает на входной объект, `x19` — на выход; это согласуется с прологом соответствующей функции, где исходные `x0` и `x2` сохраняются в `x20` и `x19`. Функции **не вызывались целиком**.

| Модель | Функция | Sharp начало → конец | NR начало → конец | Clarity начало → конец |
|---|---|---|---|---|
| X-H2 5.30 | `02e623f4` | `02e62f14 → 02e62f4c` | `02e62f4c → 02e62f84` | `02e634c0 → 02e634fc` |
| X-H2S 7.30 | `03179358` | `03179e78 → 03179eb0` | `03179eb0 → 03179ee8` | `0317a424 → 0317a460` |
| X-T5 4.31 | `02da0948` | `02da14a8 → 02da14e0` | `02da14e0 → 02da1518` | `02da1a64 → 02da1d0c` |
| X100VI 1.31 | `0307104c` | `03071bc0 → 03071bf8` | `03071bf8 → 03071c34` | `03072194 → 03072440` |

| Модель | Вход `x20+sharp / NR / clarity` | Один прямой вызов функции |
|---|---|---|
| X-H2 | `39b0 / 39d8 / 3f34` | `02e1e128` |
| X-H2S | `3954 / 397c / 3ee0` | `03136704` |
| X-T5 | `39f8 / 3a20 / 3f6c` | `02d5b9c8` |
| X100VI | `3fe0 / 4008 / 4560` | `03027478` |

Смещения — hex; у X100VI большие смещения формируются через промежуточное `add`. На X-H2 пролог `02e62404..40c` задаёт `x20=x0`, `x19=x2`; далее `02e62420..2c` инициализирует заголовок объекта, а позднее код пишет данные. В выбранном статическом вызове `02e1e118` передаёт `x2=0x042711d0`, `02e1e128` вызывает функцию; `02e1e12c..13c` передаёт тот же адрес как `x1` и длину `0x274` в `014d2534`, ранее исследованную как копирование. Это статический контекст, не выполненная непрерывная трасса и не доказательство последующей обработки изображения. Окна вызова и прологи всех моделей сохранены в JSON. Не показано, что глобальный объект соответствует конкретному состоянию съёмки.

## Исполненные фрагменты

Выходные поля расположены по **невыровненным** смещениям `x19+0x249`, `+0x24d`, `+0x269` соответственно. Наблюдаются записи четырёх little-endian байтов; таблица показывает их как signed32. Другие смещения могут иметь другой смысл. Исследователь задаёт внутренние коды, не подтверждённые значения UI.

| Внутренний вход | Sharp выход | NR выход |
|---:|---:|---:|
| 0 | −40 | 32768 (`0x8000`) |
| 1 | −30 | 28672 (`0x7000`) |
| 2 | −20 | 16384 (`0x4000`) |
| 3 | −10 | 12288 (`0x3000`) |
| 4 | 0 | 8192 (`0x2000`) |
| 5 | 10 | 4096 (`0x1000`) |
| 6 | 20 | 0 |
| 7 | 30 | 24576 (`0x6000`) |
| 8 | 40 | 20480 (`0x5000`) |

Для clarity проверены все входы от −5 до +5: выход равен входу ×10, например −5 → −50, 0 → 0, +3 → 30, +5 → 50. Эти отображения наблюдены отдельно для каждой модели; совпадение не доказывает идентичности функций целиком. NR не монотонен при числовом порядке кодов: 7 и 8 нельзя интерпретировать простой линейной формулой. Значение 8192 при внутреннем NR 4 — результат данного участка, не утверждение о единицах или силе шумоподавления.

Для искусственной комбинации кодов, ранее сопоставленных с нейтральными тегами, `sharp=4, NR=4, clarity=0`, получаются соответственно `0, 8192, 0`. Для кодов, ранее сопоставленных с тегами рецепта 0296, `3, 0, 3`, получаются `−10, 32768, 30`. Сравниваемые значения каждого поля получены **раздельными** запусками, не сшитой трассой. В предыдущем опыте писателя MakerNote те же отдельные коды дали `3/130`, `0/736` и `0/3000` соответственно; это разные выходы разных участков, а не взаимозаменяемые единицы.

## Отрицательные контроли

* При sharp 9, NR 9 и clarity ±6 инструкции достигают вызова до записи соответствующего поля. Хук останавливает VM **перед BL**, без подмены возвращаемого значения; байты поля остаются начальным `a5 a5 a5 a5`. Это неполный путь: после реального возврата вызванной функции код может записать значение, поэтому нельзя утверждать, что неподдерживаемый ввод оставляет поле неизменным в штатном исполнении. Адрес вызова и весь пройденный путь есть в JSON.
* Для каждого входа и каждой модели выполнен повтор с изменением двух остальных внутренних полей: их значения не изменили результат или точку остановки рассматриваемого изолированного фрагмента. Это контроль конкретной локальной зависимости, а не независимости настроек во всём тракте.
* При начальном заполнении `a5` нейтральные выходы sharp и clarity действительно записывают `00 00 00 00`; отсутствие записи нельзя спутать с нулём. NR 4 записывает `00 20 00 00`, NR 6 — четыре нуля. Выполнение полных соседних участков и проверка реальной достижимости данных регистров не проводились.

## Воспроизводимость и целостность

Из корня проекта: `python -X utf8 "Анализ_прошивки/Взаимосвязь_продолжение/Детализация/исследовать.py"`. Нужны Python, Unicorn, Capstone и существующий проектный декодер. [Сценарий](исследовать.py) распаковывает два FFLZ-блока каждой модели, загружает A затем B (при перекрытии B приоритетен), отображает остальные адреса нулями. `params=0x60000000`, `out=0x60010000`, стек `0x70000000..0x7000ffff`; на каждый опыт вручную обнуляются входы и заполняется выход `a5`. Фрагменты запускаются по отдельности, с ручной установкой регистров; входное состояние и указатели искусственные, нет снимка RAM камеры. Для недопустимых значений исполнение прерывается до диагностического вызова. Код не патчится. [Машинные результаты](результаты.json) содержат инструкции и точный путь каждого опыта, начальные параметры, выходные байты, фактический PC, окна вызовов и SHA-256 распакованных блоков. Исходные DAT только читаются, фото скрипт не открывает и не включает в артефакты.

| DAT | SHA-256 до = после |
|---|---|
| X-H2 | `be47168cb075ef726e67cb4bb08175a896047a3b0de2bcb6e65333b22cfcb203` |
| X-H2S | `87c566c1ff6343e4c7463a4ef968183f41d1f24cc63d610433d3a387b13f731b` |
| X-T5 | `790d6deecf26766188b0e506e40645e6b816addfeba39a52334349405421724e` |
| X100VI | `0d48d2ae26ac7ebab9b0e4cac56324807ec1ea8ae30df06b0b9e79066dc0a14a` |

Не установлены происхождение внутренних кодов, точное назначение формата выходного объекта, доставка его полей в обработчик изображения, реальные алгоритмы и любые аппаратные регистры для этих трёх настроек. Предыдущий [опыт пакетного переноса ISP](../../Последовательное_исследование/Этап_4/Семантика_ISP/Отчёт.md) касается других данных; приравнивать эти участки нельзя.
