# Встроенные имитации плёнки X-H2 и извлечение их параметров

Проверка прошивки 5.30 от 30 октября 2026 года.

Из предоставленного FWUP0028.DAT удалось извлечь служебный словарь числовых кодов имитаций плёнки и ряда настроек изображения. В этот раз результатом являются пары «название – значение» из двоичных записей, а не только поиск текстовых строк.

Полные цветовые преобразования встроенных имитаций пока не восстановлены. Полученные коды позволяют разобраться в выборе режимов и кодировании настроек; они не задают математическую формулу цвета.

## Что в камере называют рецептом

Практически полезно различать три уровня.

| Уровень | Что задаёт | Что удалось установить |
| --- | --- | --- |
| Встроенная имитация плёнки | Базовый характер обработки, например Classic Chrome или ACROS | Найдены названия и внутренние коды перечисления |
| Дополнительные настройки изображения | Баланс белого, обработку светлых и тёмных участков, резкость, зерно и другие регулировки | Извлечены словари состояний ряда регулировок |
| Пользовательский набор C1–C7 | Сохранённое сочетание настроек конкретной камеры | Текущие наборы владельца по общему файлу обновления определить нельзя |

Fujifilm описывает рецепт как сочетание базовой имитации плёнки с дополнительными настройками качества изображения. Поэтому выбранный режим и дополнительные регулировки нужно рассматривать вместе. [Пояснение производителя о рецептах](https://www.fujifilm-x.com/en-gb/learning-centre/how-to-access-film-simulation-recipes/).

Пример структуры пользовательского рецепта: Classic Chrome, выбранный баланс белого и его сдвиг, настройки светлых и тёмных участков, цвета, резкости, подавления шума, зерна и эффектов цвета. Любые конкретные значения такого набора принадлежат самому рецепту. Из названия Classic Chrome они автоматически не следуют.

Для C1–C7 сохраняются и другие параметры съёмки. Это следует учитывать, когда переключение рецепта неожиданно меняет поведение камеры. [Руководство X-H2 по пользовательским наборам](https://fujifilm-dsc.com/en/manual/x-h2/taking_photo/shooting_mode/).

## Какие числовые сведения действительно извлечены

Служебный словарь найден в блоке, который начинается в исходном DAT по смещению 0x840274. После распаковки начало группы имитаций находится по смещению 0x878F58 внутри этого блока.

Каждая исследованная запись занимает 16 байт: 8 байт ссылки на строку и 8 байт числового значения. Ссылка разрешается в корректное название; затем проверяется значение следующего поля. Для группы имитаций проверены 26 последовательных записей с кодами от 0 до 25.

Примеры из файла владельца:

| Название в словаре | Код, десятичный | Код, шестнадцатеричный |
| --- | ---: | --- |
| UI_FILM_SIM_CLASSIC_CHROME | 14 | 0x0E |
| UI_FILM_SIM_REALA | 17 | 0x11 |
| UI_FILM_SIM_ETERNA | 18 | 0x12 |
| UI_FILM_SIM_BLEACH_BYPASS | 19 | 0x13 |
| UI_FILM_SIM_ACROS_FILTER_NON | 21 | 0x15 |
| UI_FILM_SIM_ACROS_FILTER_R | 22 | 0x16 |
| UI_FILM_SIM_ACROS_FILTER_Y | 23 | 0x17 |
| UI_FILM_SIM_ACROS_FILTER_G | 24 | 0x18 |

Например, запись Classic Chrome находится по смещению 0x879038 распакованного блока. Она содержит ссылку 0x031C8E60 на строку UI_FILM_SIM_CLASSIC_CHROME и значение 14.

Эти числа относятся к конкретному служебному перечислению этой прошивки. Они не установлены как коды EXIF, команды USB, положение значения в сохранённом наборе или числовые коэффициенты обработки.

26 записей не означают наличие 26 доступных имитаций. В словаре есть групповые обозначения фильтров, автоматический вариант и названия, назначение которых требует отдельного сопоставления. Соответствие внутренних сокращений F1B, F1C, F2, SUPERIA и AMERICAN_NEW_COLOR экранным названиям в этой работе не подтверждено; их нельзя определять только по порядку строк.

Полный список сохранён в файле Имитации_плёнки.tsv.

## Как кодируются регулировки изображения

Наиболее показательные результаты:

| Регулировка | Названное значение | Код перечисления |
| --- | --- | ---: |
| Чёткость | +5 | 0 |
| Чёткость | 0 | 5 |
| Чёткость | −5 | 10 |
| Светлые участки | +4 | 0 |
| Светлые участки | +3,5 | 1 |
| Светлые участки | 0 | 8 |
| Светлые участки | −2 | 12 |
| Тёмные участки | 0 | 8 |
| Сдвиг баланса белого по R | 0 | 9 |
| Сдвиг баланса белого по B | 0 | 9 |
| Зерно, обозначение HIGH | Сильный вариант по названию | 0 |
| Зерно, обозначение OFF | Выключено | 2 |

Числовые значения чёткости, светлых и тёмных участков, а также сдвигов баланса белого явно присутствуют в обозначениях записей. Например, UI_HIGHLIGHT_P3p5 содержит значение +3,5, а UI_HIGHLIGHT_M1p5 – значение −1,5.

Для этих перечислений получаются такие соответствия:

- чёткость: названное значение = 5 − код, для кодов 0–10;
- светлые и тёмные участки: названное значение = 4 − код / 2, для кодов 0–12;
- сдвиги баланса белого R и B: названное значение = 9 − код, для кодов 0–18.

Это правила перевода кодов в названия значений. Формулы обработки пикселей они не описывают.

В нейтральном положении чёткости используется код 5, а для светлых участков – код 8. Поэтому найденный в данных ноль не следует автоматически понимать как «настройка изображения установлена в 0». Нейтральное значение также не устанавливает заводское значение по умолчанию.

Словари цвета, резкости и подавления шума содержат по девять состояний. Для них сохранены исходные названия и коды. Если название не содержит явного числа, в выгрузке не подставлено предполагаемое экранное значение.

Выгружены 255 строк связанных состояний и 17 кодов самих параметров. В число состояний входят служебные варианты; это не количество доступных пользователю настроек.

Некоторые коды параметров:

| Обозначение | Код параметра |
| --- | --- |
| UI_SETP_FILM_SIM | 0x68E |
| UI_SETP_CLARITY | 0x605 |
| UI_SETP_DRANGE | 0x6A6 |
| UI_SETP_STILLCOLOR | 0x6B3 |
| UI_SETP_SHARPNESS | 0x6B5 |
| UI_SETP_HIGHLIGHT | 0x6B9 |
| UI_SETP_SHADOW | 0x6BB |

Код параметра отвечает на вопрос «какая настройка», а код его состояния – «какой вариант». Например, 0x68E относится к параметру имитации, а 14 – к варианту Classic Chrome в отдельно найденном перечислении. Связь этих двух словарей с конкретным форматом сохранённых настроек ещё требует разбора.

## Почему найденная запись не всегда означает доступную функцию

В общем перечислении динамического диапазона присутствуют DR800 и DR1600. Руководство X-H2 перечисляет штатные варианты AUTO, 100%, 200% и 400%. Одного присутствия дополнительных названий в словаре недостаточно, чтобы считать их скрытыми работающими режимами камеры. [Настройки качества изображения X-H2](https://fujifilm-dsc.com/en/manual/x-h2/menu_shooting/image_quality_setting/).

Аналогично в перечислении чёткости есть служебное обозначение AUTO. Оно не добавлено в список подтверждённых доступных вариантов.

Это существенное ограничение для дальнейшего извлечения: служебные словари могут сохранять общие, старые или неиспользуемые обозначения. Доступность нужно устанавливать по коду, таблицам меню и поведению камеры.

## Можно ли извлечь сам характер Classic Chrome или REALA

Для точного воспроизведения встроенной имитации вне камеры нужно установить, какие преобразования выполняются над изображением и какие данные они используют. Предметом дальнейшего поиска могут быть цветовые таблицы, тональные зависимости, коэффициенты и вызывающие их функции. Их формат, принадлежность конкретным имитациям и порядок применения пока не подтверждены.

Поэтому сейчас можно:

- получить внутренние названия и коды выбора режимов;
- получить коды ряда регулировок и восстановить явно названные значения;
- искать обработчики настроек по найденным обозначениям и кодам;
- сравнивать настройки пользовательских рецептов, когда доступны их фактические значения.

Пока не получены:

- подтверждённый полный набор математических преобразований каждой имитации;
- цветовые таблицы в проверенном формате для применения в другой программе;
- таблица вида «встроенный Classic Chrome = такие-то значения всех обычных регулировок»;
- значения рецептов, которые владелец сохранил в C1–C7 своей камеры.

Из найденного не следует, что каждая встроенная имитация сводится к нескольким обычным регулировкам поверх одного общего режима. Выбор имитации и дополнительные настройки представлены разными параметрами.

Цифровая подпись не помешала чтению и извлечению этих данных. Изменение прошивки для этой работы не потребовалось.

## Проверяемые результаты

В этом каталоге сохранены:

- Имитации_плёнки.tsv – 26 записей словаря режимов;
- Настройки_изображения.tsv – 255 записей связанных состояний;
- Коды_параметров.tsv – 17 выбранных кодов параметров;
- Исходные_записи_таблицы.txt – байты записей группы имитаций и результат их разбора;
- Доказательства_извлечения.json – контрольные суммы, смещения и сведения о проверках;
- извлечь_параметры.py – программа повторного извлечения.

Смещения записей относятся к распакованному блоку. Прибавление такого смещения к 0x840274 не даёт адрес записи в исходном сжатом DAT.

При повторном запуске программа проверяет SHA-256 исходного файла, контрольную сумму распакованного блока, последовательность записей имитаций и несколько независимых соответствий числовых состояний. Исходный DAT открывается только для чтения.

Команда повторного извлечения:

~~~powershell
python '<корень проекта>\Анализ_прошивки\Рецепты\извлечь_параметры.py'
~~~

Для следующего уровня исследования уже есть предметная точка входа: проследить обработку выбора имитации и установить, какие таблицы или функции меняются при переключении конкретной пары, например стандартного режима и Classic Chrome.
