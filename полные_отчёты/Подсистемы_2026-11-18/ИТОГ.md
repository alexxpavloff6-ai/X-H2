# Итог: стабилизация, управление записью и видео X-H2 5.30 (18.11.2026, седьмой круг)

Координатор — Claude Opus 5.5; исполнители Codex gpt-6-luna (xhigh): W1 стабилизатор (2 захода; координатор указал имена BLUR/BLURRING_CORRECT), W2 reccont, W3 видео. Камера не использовалась.

## Главное

1. **Стабилизация (W1, Д).** У Fujifilm стабилизация — «коррекция размытия». `UI_SETP_BLURRING_CORRECT_MODE` (0x0F) = IS MODE: варианты ALWAYS, ALWAYS_MOVE, OCCASION, OCCASION_MOVE, CENTER (USB 1, 5, 2, 6, 3); сеттер `0x2C8B594` по таблице `0x18B9D90` раскладывает выбор на пару «режим (0/1/2) + признак движения», пишет режим через `0x1337A04` в 0x0F (фото) или 0x10 (видео, если активный режим = 0x2D) и пересчитывает `MOVE_DETECT` 0x12 через `0x1337AA0`. Видео: `BLURRING_MOVIE` 0x10 (механическая / механическая+электронная / выкл.), `BLUR_CORRECTION_MOVIE` 0x11 (усиление / обычная). Банк: текущие 0x2A3/0x2A5/0x2A6, слоты C1 0xF7AE (+0x400). Во всех 49 копиях IS MODE = 1 (постоянно). Режим доходит до поля верхнего дисплея 0xAD8 (`0x2BD5114`); **связь с biscom не найдена** — biscom (`0x13FEF34`, коды 0x19AF–0x19E0, знаковое 12-битное поле в 0x19B5) остаётся вероятной, но не доказанной службой стабилизатора.
2. **Управление записью reccont (W2).** Запись 0x03, 47 отправителей; цикл `0x2D67134` → проверка состояния `0x2E00D18` → обработчики `0x2D9A060`, `0x2D5B36C` (коды 0x200–0x22E); события 0x204 (12 байт), 0x205 (4), 0x206 (44), 0x1212–0x1214 (пустые), 0x1220–0x1222 (состояния 3/2/4). Чтений настроек серии/затвора/режима в этих обработчиках нет; смысл событий (спуск, экспозиция, кадр, видео) и путь к файлу статически не устанавливаются (граница — нужна трасса на камере).
3. **Видео (W3, Д по коду).** 40 настроек на общем сеттере/геттере; `MOVIE_PIXEL` (`0x2C8E49C`) согласует пропорции по таблице `0x18BBFC8`; `MOVIE_FPS` (`0x2C8E65C`) — через обработчик `0x12EB7B4`; HS-видео — `0x1302D8C/0x1302E2C/0x13030AC`; ProRes-прокси (`0x2C8EC6C`) и носитель (`0x2C8EA20`) учитывают друг друга; HDMI RAW раздельно для Atomos/Blackmagic. Соответствие числовых кодов пунктам меню и полные таблицы сочетаний не восстановлены; значения в копиях не менялись, поэтому проверены только адреса.

## Что это даёт для доработок

- Образец «одна настройка меню → несколько внутренних полей» повторяется (зерно, IS MODE, разрешение видео): правка вариантов меню требует правки таблицы перевода и всех связанных полей.
- Фото и видео делят одни ветки сеттера; поведение переключается по активному режиму (0x2D = видео) — это ключ к тому, как камера разводит фото- и видеонастройки.
- Работа самих подсистем (стабилизатор, контур записи) статически видна только как очереди сообщений; их смысл закрывается опытами на камере (изменение IS MODE / видеонастроек с копиями до и после) и трассой.

## Опыт на камере (18.11.2026, `опыт_камера/итог_опыта.md`, Д)

Коды банка ↔ пункты английского меню: IS MODE фото CONTINUOUS 0 / SHOOTING ONLY 1 / OFF 2; MOVIE MODE разрешение 4K 0 / FHD 2, частота 23.98P 0 / 29.97P 3 (номер в списке); тип файла раскладывается на три поля — кодек `MOVIE_FILE_FORMAT` (H.264 0 / H.265 1), цветовой формат `MOVIE_RGB` (H.264 420 = 0, H.265 420 = 1, H.265 422 = 3), сжатие (LongGOP 1); Bit Rate 200Mbps = 1; IS MODE видео IBIS/OIS 0 / OFF 2; BOOST ON = 1. Во всех проверенных пунктах байт банка = номер строки меню. Смена диска фото ↔ видео меняет `FRONT_CMD_ASSIGN` (20 ↔ 130) — это «контекстное состояние» 17.11.
