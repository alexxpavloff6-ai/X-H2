# R1. Размер, качество, плёнка, чёрно-белая тонировка и динамический диапазон

## Выводы

1. `D18D` — строковое имя слота, сопоставленное с `UI_SETP_CUSTOM_SAVE_NAME (0x730)`. В карте банка нет прямого поля имени, а строка C1 не найдена в резервной копии; место хранения в банке не установлено.
2. `D18E` хранит размер кадра слота одним USB-кодом, но в банке ему соответствуют два байта: `UI_SETP_PIXEL` и `UI_SETP_ASPECT`. Во всех C1–C7 USB читается `7` (L, 3:2), а в резервной копии стоят внутренние значения `0` и `1`.
3. Запись значения `0x12` в свойство `D1A5` меняла текущие `PIXEL/ASPECT`, но это другой путь, не настройка слота. По имеющимся данным нельзя заключить, что таблица D18E совпадает с таблицей текущего размера D1A5.
4. `D18F` — качество изображения. Коды USB из fujicli преобразуются; их нельзя напрямую копировать в байт `UI_SETP_QUALITY`. Наблюдённые C1–C7 значения банка: `4,4,4,2,4,4,4`.
5. `D190=0xFFFF` — USB-код Auto. В C5 ему соответствует внутренний байт `UI_SETP_DRANGE=0`; в остальных слотах DR100/200/400 хранятся как `1/2/3`.
6. `D191` — приоритет широкого динамического диапазона. Во всех слотах USB Off (`0`), а внутреннее значение банка — `4`; значит, здесь также есть преобразование.
7. `D192` задаёт имитацию плёнки. USB-коды, значения fujicli и внутренние байты различаются: например, Velvia `2` в C7 хранится как `4`, а Classic Chrome `11` в C1 — как `15`.
8. `D193` и `D194` — две оси тонировки. USB `0` во всех слотах соответствует байту `18` в каждом поле; это нулевое положение в диапазоне, с представлением со смещением. Для `D193` оценщик состояния прямо проверяет семейство `FILM_SIM`; ветка `D194` дополнительно смотрит режим и контекст, но точное назначение этих условий не установлено.
9. Z2 отмечает, что запись некоторых свойств уже проверяли, но это не доказывает связь каждого USB-кода с конкретным байтом банка. В этой задаче новых записей на камеру не делали; неподтверждённые связи помечены **К**.

## Путь обработки

Общие точки прошивки те же, что и в разборе зерна: сеттер `0x2C88E98` использует таблицу переходов `0x33A77E8` с индексом `id−0xB`; обратный диспетчер `0x2C93FD4` использует таблицу `0x33A929C` с индексом `id−0xF`. Преобразование значений проходит через `0x1135930` и таблицы указателей `0x1BD5AB8 + 8·id`; сохранение значения UI_SETP в банке выполняет `0x11335C4`. Для перечисленных свойств ID UI_SETP — кандидаты уровня К, взятые из Z2 и сверенные с картой банка.

### Размер D18E и проверка по D1A5

В таблице прошивки `0x18BBCF0` находится набор 26 режимов размера: каждая запись содержит связанные характеристики пикселя/соотношения сторон и параметры размера. В ветке `0x2C8E1C4` поиск по этой таблице ведётся по значению, затем вызываются функции обновления пикселя и соотношения сторон. Однако это не доказывает, что USB-код слота `D18E` индексирует ту же таблицу тем же способом: ветка может обслуживать текущее состояние, а преобразование слота может быть отдельным слоем.

Наблюдение из D1A5 — запись значения `0x12` в свойство давала текущие `PIXEL=1`, `ASPECT=0`; а слот D18E=7 при чтении банка имеет `PIXEL=0`, `ASPECT=1`. Значения различаются, поэтому нельзя вывести из одного наблюдения общую таблицу. Чтобы закрыть вопрос, нужен безопасный однофакторный опыт именно с записью D18E в слот, но камера в этой задаче не использовалась.

### Auto и приоритет DR

`D190=0xFFFF` — специальный USB-код Auto, а не значение, записываемое в однобайтный банк. Сверка C5 показывает внутренний байт DRANGE `0` при чтении USB `65535`; при явных DR100/200/400 байты равны `1/2/3`. В Z3 отдельно найдено, что при подготовке параметров проявки Auto заменяется значением 100 — это правило последующей обработки, оно не меняет значение, сохранённое в слоте.

Связь `D191` с `D190` ограничена правилом протокола fujicli: задавать DR следует только когда WIDEDRANGE выключен. В текущих данных во всех семи слотах `D191=Off`, поэтому наблюдения не показывают поведение при других приоритетах. Наличие внутреннего поля `UI_SETP_WIDEDRANGE` и ветвей сеттера/геттера подтверждено картой банка и прошивкой; полный набор переходов для не-Off по имеющимся слотам не проверен.

## Ограничения вывода

- PTP-описатели `D18E–D1A5` в доступном снимке отсутствуют: запрос описателя завершался `0x2002` без данных. Тип и диапазоны, кроме сопоставлений из fujicli, не следует выдавать за полученные из PTP-описателя X-H2.
- В Z2 для `D18F`, `D190`, `D191`, `D192` указана проверенная запись. Эти результаты подтверждают запись свойства, но в R1 их журналы не пересматривались и отдельно не воспроизводились; значения байтов в этом отчёте взяты из резервной копии. Для `D18E`, `D193`, `D194` запись в Z2 не отмечена как проверенная.
- Сопоставления поля банка с USB опираются на карты обработчиков, совпадающие значения семи слотов, fujicli и найденные ветви диспетчеров. Это уровень К, пока не проверен путь каждого свойства эмуляцией или однофакторным изменением.

## Что это даёт для будущих доработок прошивки

Для чтения и записи слота надо сохранить отдельный слой преобразования между USB-кодами и байтами банка. Auto DR следует трактовать как особый код USB и отдельное внутреннее состояние; не записывать `0xFFFF` в байт. Пару PIXEL/ASPECT надо менять согласованно после восстановления таблицы D18E. Для `BLACK_TONE` учитывать проверенную связь с семействами Monochrome/Acros; для `BLACK_TONE_RG` отдельно исследовать условия режима и контекста.

## Материалы и воспроизведение

- `extract_bank.py` повторно извлекает байты восьми числовых полей из указанного резервного образа и сверяет значения с картой банка; также ищет буквальную строку имени C1 в образе.
- `extract_tables.py` сохраняет выбранные таблицы преобразования и таблицу размеров из блока 0 в `таблицы_преобразования.json`.
- База для анализа: `Зерно_2026-11-18/КОНТЕКСТ.md`, `Зерно_2026-11-18/ИТОГ.md`, отчёт и JSON Z2, карта банка `Камера_2026-11-17/K2_прошивка/карта_банка.tsv/.json`, сырой список слотов `PTP_чтение_2026-11-10/xh2_slots_C1-C7_072426.txt`, `fujicli` `option.cue`, отчёт Z3.
- Бинарные адреса относятся к X-H2 5.30. Ветви сеттера находятся в блоке 1; таблицы преобразования размера `0x18BBCF0` и общие функции преобразования находятся в блоке 0.
