# Задача E: кто вызывает запись свойства 0x2B9 (settings+0x144) и откуда значение 0x2C

Папка для записи: `<корень проекта>\Анализ_прошивки\Сравнение_версий_2026-11-16\E_сеттер_0x2B9`

Цель: связать код режима `0x2C` (свойство `0x2B9`, копируется в RECF `[ctx+0x3978]`, при `0x2C` включается многокадровый путь `recfCalcRecifParam` `0x2dd1f9c`) с конкретным режимом съёмки (ISO BKT / FILM SIMULATION BKT / другое).

Известно (X-H2 5.33): хранилище свойств в блоке 0 — запись `0x128c5d8: strb w19,[x0,#0x144]` (адрес = `0x2624a88 + slot*0x12768 + 0x1000`), за ней лог с `mov w0,#0x2b9; bl 0x11da148` (`0x128c600`, `0x128c614`); у `0x128c5d8` нет прямых bl-вызовов — это тело большой функции/switch по id. Общий API установки свойства — `0x11335c4(id, value, ...)` (434 вызова в блоке 0, 3727 в блоке 1), сброс `0x2c240ec: mov w1,#0x1affffff; mov w0,#0x2b9; bl 0x11335c4`. Блок 0 `0x1137b0c..0x11383a4` — отображение индекса поля в id (8 -> 0x2b9, 7 -> 0x2b8).

## Что выяснить
1. Найти функцию, внутри которой лежит `0x128c5d8`, её вход и способ выбора ветки (switch/jump-таблица по id), и восстановить цепочку от `0x11335c4` (или другого API) до этой ветки для id `0x2B9`.
2. Найти ВСЕ вызовы API установки свойств, где id = `0x2B9` получается НЕ литералом: id из таблицы (массивы {id, value}, {id, ...} — ищи u16/u32 `0x02b9` в данных блоков 0/1 и ссылки на эти таблицы), из отображения индекс->id (`0x1137b0c`: кто его вызывает и с каким индексом 8), из кода события (`0x358 - 0x9F`).
3. Для каждого такого пути — откуда значение: константа, таблица значений пункта меню (u8/u16 массивы рядом с UI-строками), вычисление по другим свойствам. Найти таблицу, в которой встречается `0x2C` как значение для этого id, и строки рядом (UI_SETP_*, DRIVE, BKT, ISO_BKT, FILM_SIM_BKT, MULTI_EXPO, HDR, PIXEL_SHIFT, ...). Таблица UI-имён `0x3216a90` (BRACKET=0x3F, MULTI_EXPO=0x40, DRIVE_MODE=0x4C, ISO_BKT=0x5A) — используй как подсказку.
4. Восстановить, если возможно, весь домен значений свойства `0x2B9` (0x00..0x2D) с именами режимов; ответить, что такое `0x2C` (и `0x2D`).
