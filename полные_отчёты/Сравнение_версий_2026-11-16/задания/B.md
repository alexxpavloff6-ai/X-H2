# Задача B: XF30mm Macro — подтвердить lens ID 0x411 и восстановить цепь до фокусировки

Папка для записи: `<корень проекта>\Анализ_прошивки\Сравнение_версий_2026-11-16\B_объектив_0x411`

## Что выяснить
1. Доказать или опровергнуть, что lens ID `0x411` = XF30mmF2.8 R LM WR Macro. Искать таблицы объективов: строки названий объективов (XF/XC/GF, `30mm`, `Macro`), массивы ID (`0x4xx` подряд), таблицы с ID + параметрами, switch/cmp по соседним ID (`0x410`, `0x412` и т.д.), PTP/EXIF lens model. Сопоставить с известными фактами (например, порядок выпуска объективов Fujifilm и их ID, если найдётся таблица с несколькими узнаваемыми именами).
2. Восстановить, куда идут `output+0x50` и `output+0xa0` из операций `0x1e`/`0x20` (потребитель X-H2 `0x2ce70e4` и дальше): какая команда объективу/модулю фокуса формируется, что означают 228/280/256 (угол поворота кольца? шаг? передаточное число?).
3. Определить смысл свойств `0x1dba` и `0x1db3` (кто их пишет, связь с настройкой FOCUS RING / LINEAR / угол поворота, MF assist). Объяснить, почему для 0x411 старая логика ломала ручную фокусировку при нестандартном угле.
4. Проверить, связаны ли с этим исправлением helper `0x58a58c` (KEY_ND_FILTER/KEY_TELE_CONVERTER) и проверка `request+0x25` или это отдельные изменения.
5. VM-контроль для ключевых веток во всех трёх моделях, где возможно.

## Общие условия
- Сначала прочитай `<корень проекта>\Анализ_прошивки\Сравнение_версий_2026-11-16\КОНТЕКСТ.md`: там пути, адреса, модуль `fwcommon.py` и уже установленные факты.
- Писать можно ТОЛЬКО в свою папку (указана ниже). Не изменяй DAT, `blocks/`, `fwcommon.py`, `КОНТЕКСТ.md` и чужие папки. Если нужен свой хелпер — положи копию в свою папку.
- Только статический анализ и Unicorn. Никаких операций с камерой, модификации или перепаковки прошивки, сетевых загрузок.
- Язык отчёта — русский.
- Результат: `отчёт.md` (выводы с адресами old→new для всех трёх моделей, инструкции, VM-контроли, уровень доказательности: доказано / сильный кандидат / гипотеза; что проверено и опровергнуто), скрипты `*.py`, которыми получены выводы (запускаемые повторно), и `доказательства.json`.
- Если гипотеза не подтвердилась — это тоже результат: опиши, что именно проверено. Ненулевой код выхода отдельного эксперимента не означает провал задачи.
- Задача считается выполненной, когда `отчёт.md` написан и отвечает на каждый пункт «Что выяснить» (хотя бы как «не удалось, проверено X/Y»). В worker_done дай краткую сводку ключевых выводов с адресами и путь к отчёту.
