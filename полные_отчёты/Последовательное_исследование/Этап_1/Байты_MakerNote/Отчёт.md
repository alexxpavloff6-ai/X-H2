# Точные байты настроек в JPEG и RAF-превью X-H2

## Зачем выполнена проверка

Для последующего сопоставления с кодом прошивки повторно прочитаны не только интерпретации ExifTool, но и сами записи Fuji MakerNote в тестовой серии. Сценарий следует цепочке `JPEG APP1 Exif → TIFF IFD0 → ExifIFD → MakerNote (0x927c) → IFD FUJIFILM`, а не ищет случайное совпадение слова FUJIFILM в файле. У RAF читается **встроенное JPEG-превью**, не массив данных сенсора. Теги не доказывают, каким путём код формировал файл или какие инструкции выполнялись в камере.

Записи содержат ID тега, тип TIFF, количество элементов и значение. Интерпретация `FilmMode` и `Saturation` по [таблице ExifTool для FujiFilm](https://exiftool.org/TagNames/FujiFilm.html), а не получена из самих идентификаторов.

## Результаты

| Исходники | Контейнер | FilmMode, тег `0x1401` | Saturation, тег `0x1003` | ImageGeneration, тег `0x1436` |
|---|---|---:|---:|---:|
| 0292, 0295 | RAF-превью и отдельный JPEG | `0x0600` / Classic Chrome | `0x0000` / 0 | 0 |
| 0293, 0294 | RAF-превью и отдельный JPEG | `0x0600` / Classic Chrome | `0x0100` / +2 | 0 |
| 0296, 0297 | Только RAF-превью | `0x0800` / Classic Negative | `0x0080` / +1 | 0 |
| 0298, 0299 | RAF-превью и отдельный JPEG | `0x0b00` / Reala ACE | `0x0000` / 0 | 0 |
| 0300 | Камерная проявка | `0x0800` / Classic Negative | `0x0080` / +1 | 1 |
| 0301 | Камерная проявка | `0x0800` / Classic Negative | `0x0000` / 0 | 1 |
| 0302 | Камерная проявка | `0x0800` / Classic Negative | `0x0100` / +2 | 1 |

Пример для 0300: запись FilmMode — `01 14 03 00 01 00 00 00 00 08 00 00`; ID `0x1401`, тип SHORT (3), число элементов 1, младшие два байта значения `00 08` = `0x0800` в little-endian. Запись Saturation — `03 10 03 00 01 00 00 00 80 00 00 00`, значение `0x0080`. Коды насыщенности — перечисление, а не линейные проценты. Остальные непосредственные 12-байтные записи и хеши каждого источника сохранены в JSON.

Метаданные соответствуют сообщению владельца об исходной RAW-съёмке и камерных проявках. Отдельных JPEG 0296 и 0297 в проверенной серии нет; 0300–0302 — не эти отсутствующие оригиналы. Чтение превью RAF не подтверждает полной идентичности его обработки отдельному JPEG.

## Воспроизведение

Из корня проекта: `python -X utf8 Анализ_прошивки/Последовательное_исследование/Этап_1/Байты_MakerNote/проверить.py`. Нужен только Python. Сценарий читает 17 существующих исходных файлов, сравнивает SHA-256 до и после чтения каждого, записывает только [байты.json](байты.json) рядом с собой. Сохранены только выбранные семь фотографических тегов, не содержимое изображений, GPS или серийные номера. Проверка до/после относится только к интервалу выполнения.

Предел: интерпретация имени и экранного значения следует внешней таблице, а не доказанному пути UI→код→MakerNote. Происхождение новых JPEG из 0296.RAF основано на сообщении владельца и согласующихся метаданных, не устанавливается одним тегом.
