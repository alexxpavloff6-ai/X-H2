# S1 — затвор, серия, экспозиция и LCD-флаг

## Краткие выводы

1. Меню типа затвора хранится в `UI_SETP_SHUTTER_TYPE` (`0x827`, байт файла резервной копии `0x63A`). Его код — не то же самое, что фактически выбранный затвор: фактический выход находится отдельно в `UI_SETP_DOTLCD_SHUTTERTYPE_OUTPUT` (`0xAB8`, файл `0x1A8`).
2. Тип затвора — MS `0`, ES `1`, MS+ES `2`, EF `3`. В режиме MS+ES выдержка 1/16000 дала фактический ES; это подтверждено снимком `02B`.
3. Текущий признак серийной съёмки — `UI_SETP_CONTINUOUS` (`0x858`, файл `0x4F8`), а выбранный режим серии виден в двух зеркальных выходах `0xACE/0xACF` (файлы `0x68C/0x68D`): CH кодируется `21`, CL — `23`. Сеттер серии меняет и связанные состояния режима, а не только один байт.
4. Выдержка M хранится как индекс `UI_SETP_SHUTTER_SPEED_M` (`0x8A0`, файл `0x5B2`). В проверенных снимках: индекс `38` = 1/25, `52` = 1/250, `67` = 1/8000, `70` = 1/16000. Отдельный выход `0xAAB` (`0x18C`) хранит знаменатель ×100.
5. Оценщик LCD-флага использует фактический тип затвора, категорию выдержки и дополнительный гейт режима. Таблица `0x3456B20` выдаёт условие только для фактического ES и выдержки не медленнее 1/600; снимки подтверждают, что в проверенном диапазоне первая включающая ступень — 1/640.
6. Полная наблюдаемая комбинация для LCD-гейта: CH, `REC_VIEW=CONTINUOUS`, фактический ES и выдержка от 1/640 и короче. В резервной копии режим экрана — `UI_SETP_REC_VIEW` (`0xB`, файл `0x29B`, `2=CONTINUOUS`, `3=OFF`).
7. Перезаписанные выходные поля затвора и выдержки могут оставаться старыми до перезапуска питания. `02B/02C` и `07/07B/07C` показывают, что меню и выходы нельзя считать одним состоянием.
8. Фактический затвор и фактическую выдержку формирует более глубокий путь съёмочного управления. В блоках 0/1 найден синхронизатор выходов, но окончательный писатель исходного поля фактического затвора не установлен.
9. `MODE_RECORD` — отдельная система режимов P/S/A/M, не один из найденных переключателей затвора/серии. Для ISO, диафрагмы и экспокоррекции существуют отдельные PTP-свойства; их нельзя отождествлять с вычисляемыми LCD-выходами.

## Границы и способ проверки

Использованы только файлы X-H2 5.30, декодированная карта банка и резервные копии снимков от 17.11.2026. Камера не подключалась. Байты были повторно прочитаны скриптом `сверка_снимков.py` из `backup.bin` по `container_offset` карты `Камера_2026-11-17/K2_прошивка/карта_банка.tsv`; сводка всех доступных снимков сохранена в `сверка_снимков.json`.

Общий сеттер `0x2C88E98` выбирает ветку из таблицы `0x33A77E8` по индексу `id−0xB`; общий геттер `0x2C93FD4` использует `0x33A929C` и индекс `id−0xF`. Базовые преобразования проходят через `0x1135930` и `0x11335C4`. В уровнях уверенности **Д** означает прямое подтверждение кодом/байтами/эмуляцией, **К** — согласованную связь, для которой часть семантики выведена из данных, **Г** — рабочее предположение.

## Карта настроек

### Тип затвора — `0x827 UI_SETP_SHUTTER_TYPE`

- Банк: текущий байт файла `0x63A`; C1-поле карты банка имеет `container_offset=0x63A`, тип `u8`.
- Значения в текущей конфигурации: `0=MS`, `1=ES`, `2=MS+ES`, `3=EF` (**Д** по таблице и однофакторным снимкам).
- Сеттерная ветка `0x2C9154C`: `0x11335C4(0x827, value, 0)`, затем вызов `0x12ECE24` с преобразованным входом и уведомление `0x132FFC8`; далее общий выход `0x2C8ECF8`. Это больше простой записи, но сама ветка не пишет поле фактического затвора `0xAB8`.
- Геттерная ветка `0x2C99744` преобразует хранимое значение через `0x1135930`.
- USB-код затвора `D03C` присутствует в SDK/реестре, однако не входит в выявленный набор свойств X-H2 5.30; поэтому связь `D03C` с пользовательским свойством камеры не подтверждена (**Д отрицательно по списку свойств**).

### Серия / DRIVE — `0x858 UI_SETP_CONTINUOUS` и соседние поля

- `0x858`: файл `0x4F8`, `u8`; в снимках `0=S`, `1=серийный режим включён`.
- `0x859 UI_SETP_CONTINUOUS2`: файл `0x4F9`, `u8`.
- `0xACE/0xACF UI_SETP_DOTLCD_CONTINUOUS[2]`: файлы `0x68C/0x68D`, дублированный индекс режима; `S=0`, `CH=21`, `CL=23` (**Д** по серии однофакторных снимков).
- Скорости серии: `0x864 UI_SETP_CONTINUOUS_SPEED_H` — файл `0x4D3`; `0x866 ..._SPEED_L` — файл `0x4D4`; оба `u8`. В серии 17.11 они не менялись (`13` и `3`), поэтому смысл кодов скорости по этим снимкам не декодируется.
- Ветка `0x2C8F508` для `0x858/0x859` переводит состояние и вызывает обработчики, включая `0x13273D0`, `0x1321B28`, `0x1321D00`; после этого общий код обновляет состояние. Связанные ветки `0x2C8FCB8` для H/L-speed проверяют состояние режима съёмки и связанные параметры; при части случаев меняют режимное поле `0x874` и вызывают процедуры обновления. Значит сеттеры DRIVE/скорости имеют побочные переходы состояния, но полное назначение каждого вызова по статическому коду не установлено (**Д — ветвление/вызовы; К — смысл части связей**).
- PTP `0xD201` кодирует Drive: S=`4`, CH=`2`, CL=`3`. Для обычной съёмки это подтверждено существующими USB-данными; соответствие всех режимов с внутренними кодами выше — **Д** по серии и словарю.

### Выдержка

- В режиме M: `0x8A0 UI_SETP_SHUTTER_SPEED_M`, файл `0x5B2`, `u8`. Контрольные пары «индекс → фактическая выдержка»: `38→1/25`, `52→1/250`, `67→1/8000`, `70→1/16000` (**Д** по снимкам и выходам).
- В режиме S: `0x89F UI_SETP_SHUTTER_SPEED_S`, файл `0x5B1`; в соседнем рабочем наборе также есть S/movie/remote варианты. Сеттер `0x8A0` попадает в общий путь записи `0x2C93AA8`, который вызывает `0x11335C4(id,value,0)` и общий постобработчик `0x2C8ECF8`. Отдельной проверки/перезаписи других постоянных UI_SETP-полей в этой ветке не видно.
- Выход фактической скорости `0xAAB UI_SETP_DOTLCD_SHUTERSPEED_OUTPUT`, файл `0x18C`, `u32`, единица — знаменатель ×100: `1/8000→800000`, `1/16000→1600000`. Экранный индекс `0xABB`, файл `0x681`, также меняется отдельно.
- USB: внутренний код `0x4D1` соответствует свойству `0x500D` (выдержка в микросекундах, например 1/8000=`125`) (**Д** по PTP-картам/съёмке). Это отдельное USB-представление, не байт `0x5B2`.

### ISO, диафрагма и экспокоррекция

- PTP-карта: `0x4D0 → 0x5007` (диафрагма), `0x4D1 → 0x500D` (выдержка), `0x4D2 → 0x500F` (ISO), `0x4D3 → 0x5010` (экспокоррекция). Эти свойства являются отдельным интерфейсом управления съёмкой.
- В резервной копии есть `0x755 UI_SETP_ISO_PSAM` (файл `0x4EA`, `u8`) и связанные настройки авто-ISO. `0xAAF DOTLCD_ISO_OUTPUT` (файл `0x190`, `u32`) — вычисляемый выход, а не значение ISO: он равен `125` только в `02B` с MS+ES при 1/16000 и равен `0` в большинстве других снимков. Точный триггер этого выхода не установлен.
- Диафрагма представлена несколькими полями, зависящими от режима: `0x88F UI_SETP_FNUMBER` (файл `0x228`, `u16`), `0x898 FNUMBER_M` (файл `0x22C`), `0x899 FNUMBER_A` (файл `0x22A`) и отдельными пользовательскими полями. В снимках `FNUMBER_M=280`, тогда как `FNUMBER=0`; единица/преобразование по серии не калибровались.
- `0x883 UI_SETP_EXPOSURE` находится в файле `0x5BF`; в проверенных копиях значение `15` не менялось. Ветка сеттера `0x2C8D5C8` содержит режимные условия и при некоторых путях записывает соседние `0x884 UI_SETP_EXPOSURE_CUSTOM` и/или `0x883` через преобразование. Однако равенство этого UI-поля PTP-экспокоррекции `0x4D3/0x5010` не доказано; в отчёте они оставлены раздельно.
- Не следует путать `0x883 UI_SETP_EXPOSURE` с `0x54A UI_SETP_EXPOSURE_TYPE` (тип экспозиции, файл `0x2B3`).

### Режим P/S/A/M (`MODE_RECORD`)

Резолвер `0x1141EE0` обслуживает enum `MODE_RECORD`; коды `0x21–0x24` означают P/S/A/M, `0x2C` — HDR. Выбор режима проходит по отдельному пути (селектор `0x2E18340`), а не через один общий байт `UI_SETP_SHUTTER_TYPE` или `UI_SETP_CONTINUOUS`. В материалах также есть копирование значения в RECF-контекст `[ctx+0x3978]`, но равенство этого поля коду `MODE_RECORD` не подтверждается отдельной проверкой; не использовать его как доказательство безусловной связи (**К** для enum/селектора; связь с полем контекста требует уточнения).

### Производительность

- `0x5BA UI_SETP_PERFORMANCE` — основной параметр; текущий файл `0x410`, `u8`. Соседи: `0x5BC PERFORMANCE_LEVER` — файл `0x412`; `0x5BD PERFORMANCE_MODE` — файл `0x31B`.
- PTP `D304` использует `0x5BA` и соседний `0x5BD`; PTP-коды Normal=`1`, Boost=`5`, тогда как внутренний словарь использует иные коды. `0x513` — другое пространство внутренних номеров и не тождественно UI_SETP `0x5BA`.
- Сеттер `0x5BA` в `0x2C8DA38` вызывает преобразование/установку режима через `0x1337DFC`, `0x2BAC6D8` и условно `0x2BB0268`/`0x13199E0`; отдельная ветка `0x5BD` сохраняет значение и запускает обновление режима. Для особого значения контекста `0xF002` ветка пишет переданное значение ещё и в `0x5BC`. В копиях 17.11 значения оставались `5BA=2`, `5BC=4`, `5BD=0`.

## Кто пишет «фактический затвор» и «фактическую выдержку»

Синхронизатор `0x2BD5114` копирует поля из структуры съёмки в выходные настройки: `0xAB8 ← [0x2299498+0x19AC]` (фактический тип) и `0xAAB ← [0x2299498+0x1994]` (скорость). Поэтому это не прямые зеркала меню. Сканирование блоков 0/1 не обнаружило абсолютного писателя поля `[0x2299498+0x19AC]`; ожидается косвенная запись через указатель в более глубоком съёмочном управлении. Конкретная функция-писатель не найдена. Для выдержки найдено копирование из структуры, но полный путь, который выставляет исходное поле `+0x1994`, также не установлен. По снимкам выходы могут оставаться замороженными между включениями и становиться согласованными после перезапуска питания; механизм (сохранение при выключении или расчёт при включении) остаётся открытым.

## Связь с оценщиком LCD-флага

`0x30256EC` собирает входы, а `0x30308A0` и `0x2F85F3C` читают условную таблицу `0x3456B20`. Непосредственно проверяемые поля:

| Вход | Источник | Значение для условия |
|---|---|---|
| `fieldA` | getter `0x154CEC8`, `[struct+0xCC]` | должен быть `1`; по снимкам это гейт сочетания CH + IMAGE DISP CONTINUOUS (**К** по семантике поля) |
| `shutter_type` | getter `0x3030A18`, выход фактического затвора `0xAB8`, файл `0x1A8` | должен быть `1` (ES) |
| `fieldB` | getter `0x154CF6C`, `[struct+0xD4]` | категория выдержки; таблица включается при `fieldB≥6`, что по сопоставлению категорий соответствует не медленнее 1/600 (**Д** механика, **К** смысл/единица) |
| `drive` | getter `0x3024664`, внутренний код `{3,4}` для ветвей CH/CL | дополнительный параметр оценщика; семантика CH сопоставлена с резервными копиями (**К**) |
| fieldC и поле `+0x1CC` | getters `0x155B8EC`, `0x1552658` | передаются оценщику, но таблица `0x3456B20` от них не зависит в найденном пути |

Таблица выдаёт `2` только для типа затвора `1` и `fieldB≥6`; остальные типы дают `0/1`. При этом общий предикат гасит результат при установленных битах 4, 12, 13 или 14 в `0x4D35710`. Модельный тест и пороговые снимки подтверждают первую ступень с условием при 1/640: 1/500 — выключено, 1/640 — включено. Раннее предположение «быстрее примерно 1/600» уточнено дискретной шкалой камеры.

Четыре пользовательских фактора проявляются так: текущая серия CH (`0x858` плюс выходы `0xACE/0xACF`), фактический ES (`0xAB8`), выдержка через поле `0xAAB`/категорию fieldB, экран просмотра `REC_VIEW` (`0xB`). Условие fieldA — уже собранный гейт, а не прямое чтение `REC_VIEW` самой таблицей.

## Что это даёт для будущих доработок прошивки

- Для изменения выбора режима затвора следует различать меню-поле `0x827`, фактический выход `0xAB8` и синхронизацию из съёмочной структуры в `0x2BD5114`; правка только меню-байта не гарантирует немедленного изменения реального режима.
- Для изменения условий LCD-флага существенны таблица `0x3456B20`, оценщик `0x30308A0`, предикат `0x2FE35D4` и источник входов в структуре режима. Не следует подменять категорию fieldB индексом `0x5B2`: это разные шкалы.
- Пересчёт связанных режимных параметров сосредоточен в ветках `0x2C8F508` (DRIVE), `0x2C8FCB8` (скорость серии), `0x2C9154C` (тип затвора) и `0x2C8D5C8` (экспозиция). В частности, проверять надо не только байт настройки, но и выходные значения после повторного запуска.
- Для ISO, диафрагмы и экспокоррекции нельзя использовать вычисляемый `DOTLCD_ISO_OUTPUT` как замену соответствующим настройкам; у каждого режима есть свои активные поля и преобразования.
- Для точного объяснения отложенного писателя фактического затвора и выдержки нужен дополнительный разбор загрузочного/съёмочного пути либо трассировка при включении. Текущие файлы локализуют источник структуры и синхронизатор, но не конечную инструкцию записи.
