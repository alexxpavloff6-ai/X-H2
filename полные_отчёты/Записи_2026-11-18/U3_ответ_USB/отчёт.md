# U3. Ошибки PTP и чтение свойств X-H2 5.30

## Главные выводы

1. `0x2C05748` получает внутренний код ошибки и выбирает один из обработчиков состояния PTP по общему состоянию транзакции. Это не непосредственная функция «ошибка → код ответа PTP».
2. Для обычного пути `0x2C05748` передаёт внутреннюю ошибку в `0x2BF2248`; эта функция записывает категорию состояния в поле `0x26BDF70`. При коде `0x80000080` она ставит категорию `1`, если сессия не задала особое состояние.
3. Камерный ответ `0x201C` на три отвергнутых значения совпадает с вызовом `0x2C05748(0x80000080)`, однако прямой кодовый переход от сохранённой категории `1` к пакету ответа `0x201C` не найден. `0x2001` при успехе и `0x2002` для запроса описания свойства подтверждены журналами предыдущего разбора, а не таблицей преобразования в этой работе.
4. Внутренние коды ошибок классифицируются в несколько категорий состояния. Эти категории нельзя напрямую называть PTP-кодами ответа: код ниже сохраняет малое число `1,2,3…`, а не `0x20xx`.
5. Обработчик записи D195 — короткая обёртка `0x2C0B970`: читает слово PTP-данных, вызывает общий валидатор/преобразователь `0x2C0B844` с `id=0x108`, затем возвращается. Внутри этой обёртки нет отдельного сравнения «малый/крупный» и нет явной инверсии размера.
6. `0x2C0B844` проверяет допустимость через `0x1135944`, переводит вход по столбцу 4 таблицы `0x1BD5AB8 + 8·id` через `0x1135930` и отправляет полученный индекс через `0x2BDFBA4`. Для D195 значение 4 выбирает строку 2 таблицы зерна.
7. Внутренний обработчик `0x108` `0x2C8A2A8` трактует индекс 2 как Weak/Small, тогда как наблюдение камеры для D195=4 указывает на Weak/Large. Переворота в самом USB-обработчике D195 не видно; противоречие остаётся на границе общего преобразования/потребителя сообщения. Нельзя пока заключить, что его объясняет D023.
8. Найдены внутренние геттеры настроек (`0x2C93FD4`, включая составную ветвь `0x2C94A78` для `0x108`), но это не найденный парный диспетчер `GetDevicePropValue`: ветвь `0x108` возвращает индексы 0–4 и сама не собирает USB-коды D195 6/7. Пути к сборке D18E и текущему D1A5 не установлены.
9. Камеру не использовал. Скрипты и JSON-результат находятся только в папке U3.

## 1. Разбор `0x2C05748`

Вход `w0` сохраняется в `w19`. Функция читает режим ошибки по адресу `0x26BDF70` (вычисление: `0x26A7000 + 0xA8 + 0x14·0x1000 + 0x2EC8`). При режиме 0 она очищает состояние и выходит. При режиме 1 она читает текущий код свойства и вызывает низкоуровневый помощник `0x57D28` (блок 2) с кодом свойства и внутренней ошибкой, затем упаковывает пару через `0x2D3CE38` и передаёт исходный код в `0x2BF2248`. При других режимах функция сериализует ошибку через `0x2C33FE8` и вспомогательные процедуры `0x2D3CE6C` / `0x2D3CE38`; при ошибке сериализации повторяет путь обработки состояния.

`0x2BF2248` — классификатор внутреннего кода для поля категории состояния, а не преобразователь в ответ PTP. При ненулевом текущем режиме он ничего не меняет. При нулевом режиме он сопоставляет известные внутренние коды с категориями:

| Внутренний код | Категория, записываемая в `0x26BDF70` | Уровень |
|---:|---:|---|
| `0x80000040` | 3 | Д |
| `0x80000008` | 4 | Д |
| `0x80000010` | 6 | Д |
| `0x80000080` | 1; при дополнительном условии может стать 5 или 9 | Д |
| `0x80000100` | 2 | Д |
| `0x80002000` | 12 | Д |
| иные значения | без изменения этой категории | Д |

Для `0x80000080` исключение зависит от состояния съёмки/транзакции: при проверке контекстного поля категория может стать 5; если условие ложно, далее проверяются коды состояния `0x20`, `0x1B`, `0x18`, `0x17`, задающие категории 9, 10, 8, 7 либо общую категорию 11. Это ветвление подтверждено инструкциями, но семантические имена категорий по исходникам не восстановлены.

### Что доказано о кодах PTP

| Условие/наблюдение | Ответ PTP | Основание | Уровень |
|---|---:|---|---|
| Успешная запись свойства | `0x2001` | Наблюдения в предыдущем сеансе USB | К |
| Отказ D195=6, D18E RAW-размера и D199=0 | `0x201C` | Наблюдения камеры; перед ответом найден вызов `0x2C05748(0x80000080)` | К для связи по ветви, Г для прямого преобразователя |
| `GetDevicePropDesc` для D195 | `0x2002` | Запись предыдущего сеанса RAW CONV | К |
| `0x200A`, `0x2019` и прочие коды | неизвестно | В блоках есть многочисленные совпадения байтов, но без привязки к функции отправки их нельзя считать переводами | Г |

Найденная цепочка заканчивается внутренней категорией состояния и сериализацией сообщения. Функция, которая по завершённому PTP-запросу формирует поле кода ответа и отправляет пакет по USB, не локализована. Поэтому таблица выше разделяет реальные наблюдения PTP и внутреннюю классификацию, не выдавая категории за ответы.

## 2. Запись D195 и вопрос о перевороте размера

Дизассемблирование `0x2C0B970`:

```text
bl 0x1320800                 ; прочитать значение из PTP-буфера
and w1, w0, #0xffff
mov w0, #0x108
bl 0x2C0B844                 ; проверка и перевод к внутреннему значению
ret
```

Валидатор `0x2C0B844` вызывает `0x1135944(id, value, 4, 0)`. При успехе вызывает `0x1135930(id, value, 4, 0)` и передаёт результат как значение `id` в `0x2BDFBA4`. Общий преобразователь `0x12E67AC` ищет входное значение в четвёртом столбце выбранной таблицы и возвращает индекс строки. Для известной таблицы `0x108` это даёт `USB 4 → строка 2`.

В самом `0x2C0B970` нет арифметики по биту размера, условий по диапазону размера или перестановки индексов. Преобразователь таблицы выполняет поиск и возвращает номер строки. Далее `0x2BDFBA4` лишь публикует пару `(id, значение)` событием `0xF8`; фактический потребитель — общий сеттер `0x2C88E98` через шину — остаётся следующим местом для проверки. Если индекс 2 доходит до известной ветви `0x2C8A2A8` без изменения, та записывает Weak/Small, что не совпадает с опытом USB 4 → байты 1/1. Значит, одной этой таблицы недостаточно для объяснения наблюдения. Отдельное кодирование D023 остаётся гипотезой, не выводом.

## 3. Обратное чтение внутренних настроек

Функция `0x2C93FD4` — общий диспетчер чтения внутренних идентификаторов `UI_SETP`. Для `0x108` ветвь `0x2C94A78` читает внутренние `0x106` и `0x107`, затем собирает индекс 0–4. Значение `GRAIN=2` сводится к индексу 4; размер при этом не превращает индекс в коды D195 6/7. Следовательно, известный внутренний геттер не может быть всем путём `GetDevicePropValue(D195)`.

В этой задаче не установлен отдельный диспетчер чтения USB-свойств по текущему коду свойства `[0x26C0DF4]`, обработчик для D195/D18E/D1A5, точная выборка банка по D18C и функция упаковки `GetDevicePropValue` в пакет PTP. Адреса смещений `PIXEL`/`ASPECT` и формула для D1A5 из наблюдений не заменяют доказательство кодового пути чтения.

## 4. Что нужно проверить для закрытия

1. Проследить потребителя сообщения `0xF8` от `0x12E863C` до вызова сеттера и проверить, меняется ли индекс для `0x108` после `0x2BDFBA4`.
2. Найти вызывающий PTP-диспетчер `GetDevicePropValue` (операция `0x1015`) и соответствующую ветвь по `[0x26C0DF4]`; отдельно зафиксировать структуру/длину ответа.
3. В найденном обработчике чтения проследить выбор слота D18C и обращения к `GRAIN`, `GRAIN_SIZE`, `PIXEL`, `ASPECT`; сравнить байты с результатами всех семи слотов.
4. Найти конечный узел отправки ответа PTP. Только после этого расширять таблицу `0x20xx` для внутренних кодов, отличных от `0x80000080`.

## Уровни достоверности

- **Д** — прямое дизассемблирование функций `0x2C05748`, `0x2BF2248`, `0x2C0B970`, `0x2C0B844`, `0x12E67AC`; расчёт адреса `0x26BDF70`; ветвление и внутренние категории.
- **К** — соответствие ответов `0x2001`, `0x2002`, `0x201C` наблюдениям USB/камеры и связь `0x80000080` с отказами.
- **Г** — прямое преобразование категории статуса в PTP-код; ответы для других внутренних ошибок; диспетчер и сборка `GetDevicePropValue`; применение D18C в этом пути; окончательное объяснение несогласия размера зерна.

## Что это даёт для будущих доработок прошивки

Изменение проверки D195 и изменение PTP-ответа — разные участки. `0x2C0B844` отвечает за допустимость и перевод значения, `0x2C05748` фиксирует ошибку и выбирает путь её обработки, а наблюдаемый `0x201C` появляется позднее. Для зерна нельзя менять таблицу или ветвь `0x108`, пока не проверен фактический индекс на входе общего сеттера после события `0xF8` и не найден код чтения D195.
