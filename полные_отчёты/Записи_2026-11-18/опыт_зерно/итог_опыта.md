# Опыт 18.11.2026: кодировка размера зерна в текущих настройках (только чтение копии)

Владелец выставил в меню съёмки «Эффект зерна: STRONG, LARGE», выключил камеру с экрана съёмки, подключил в режиме USB RAW CONV./BACKUP RESTORE. Копия `01_текущее_STRONG_LARGE/backup.bin` (SHA-256 7a4e488a…); текущие `UI_SETP_GRAIN`/`UI_SETP_GRAIN_SIZE` (копия 0x4A9/0x4AA) = **0 / 1**.

| Источник | Значение | Байты GRAIN/SIZE |
|---|---|---|
| слот C3 (меню владельца) | Strong Small | 0 / 0 |
| слот C1 после записи USB D195 = 4 | Weak Large | 1 / 1 |
| текущие настройки (меню владельца) | Strong Large | 0 / 1 |

**Вывод (Д):** кодировка одна для слотов и текущих настроек — GRAIN 0 Strong, 1 Weak, 2 Off; SIZE 0 Small, 1 Large. Гипотеза «слоты и текущие настройки кодируют размер наоборот» опровергнута.

**Остаётся (К):** ветка сеттера `0x2C8A2A8` кладёт индекс 1 в (0, 1) = Strong Large, а таблица значений `0x1769350` для `0x108` сопоставляет строке 1 USB 3 («HIGH_SMALL»). Путь записи D195 (U3, эмуляция `0x1135930(0x108, USB, 4, 0)`: 1→4, 2→3, 3→1, 4→2, 5→0) отдаёт сеттеру строку, при которой USB 4 дал бы (1, 0), но камера записала (1, 1) — значит, между обработчиком D195 и сеттером есть ещё не найденное преобразование. Проверка свойства съёмки D023 (режим USB TETHER SHOOTING AUTO, текущее зерно Strong Large): предсказание при переводе через таблицу без поправки — **D023 = 3** (ошибочно «Strong Small»); правильный перевод дал бы **5**.

## Режим съёмки по проводу: D023 и разгадка (Д)

Режим USB TETHER SHOOTING AUTO, текущее зерно Strong Large, только чтение (`02_tether_D023/snapshot.json`): **D023 = 5** (Strong Large), описание свойства — список 1…5. Перевод правильный, ошибки прошивки нет.

Разгадка — таблицы перевода подзначений (`0x1BD5AB8 + 8·id`): `0x106` GRAIN `0x175C700` — строки 0, 1, 2 (сильное, слабое, выкл.); `0x107` GRAIN_SIZE `0x175C6D0` — **строка 0 → байт 1 (крупное), строка 1 → байт 0 (мелкое)**. Ветка `0x2C8A2A8` объединённой настройки `0x108` передаёт в `0x2C88E98(0x106, …)` / `(0x107, …)` **номера строк меню**, а ветки 0x106/0x107 переводят их в байты банка. Поэтому:

| USB | строка 0x108 | строки силы/размера | байты банка | проверка |
|---|---|---|---|---|
| 5 | 0 HIGH_BIG | 0 / 0 | 0 / 1 | меню Strong Large → 0/1; D023 = 5 |
| 3 | 1 HIGH_SMALL | 0 / 1 | 0 / 0 | слот C3 Strong Small |
| 4 | 2 MIDDLE_BIG | 1 / 0 | 1 / 1 | запись D195 = 4 |
| 2 | 3 MIDDLE_SMALL | 1 / 1 | 1 / 0 | запись D195 = 2 |
| 1 | 4 OFF | только сила | 2 / прежний | запись D195 = 1 |

Все наблюдения сходятся; подписи словаря Q_GRAIN верны. Прежняя ошибка разбора — значение, передаваемое в ветку 0x107, принималось за байт банка, а это номер строки меню.
