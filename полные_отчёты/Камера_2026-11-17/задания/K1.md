# K1: безопасный read-only инструмент для камеры — свойства и резервная копия настроек

Папка для записи: `<корень проекта>\Анализ_прошивки\Камера_2026-11-17\K1_камера\`

Ты — единственный исполнитель, которому разрешено обращаться к камере. Сначала прочитай `<корень проекта>\Анализ_прошивки\Камера_2026-11-17\КОНТЕКСТ.md` целиком, особенно «ПРАВИЛА БЕЗОПАСНОСТИ КАМЕРЫ» — они обязательны.

## Что сделать

1. **Документально (без камеры):** установить точные PTP-операции для
   (а) чтения значений свойств в режиме USB RAW CONV./BACKUP RESTORE (что объявляется, какие D-коды отвечают на `0x1015`);
   (б) **скачивания резервной копии настроек (BACKUP) с камеры на ПК** — какой опкод/свойство/объект, направление данных, размер/формат блоба.
   Источники: наш `PTP_чтение_2026-11-10` (логи, `Связь_USB_и_прошивки.md`), опубликованный отчёт `Внешние_инструменты` (fujicli/rawji/fujinx — как они делают backup), клон fujimod (`crates/usb/PROTOCOL.md`, `crates/catalog-service`, поиск по `backup`). Отдельно перечисли операции, которые делают RESTORE/запись — их использовать **нельзя**.
2. **Инструмент:** на основе `PTP_чтение_2026-11-10\xh2_read.py` (WPD/COM) напиши `xh2_snapshot.py` в своей папке: жёсткий белый список (только чтение), аргументы — метка снимка и папка вывода; сохраняет: DeviceInfo, все объявленные свойства с описаниями и значениями (`0x1014/0x1015`), и (если одобрено) BACKUP-блоб в файл; не перезаписывает файлы; логирует каждую отправленную операцию.
3. **Проверка в текущем режиме (MTP):** запусти снимок `00_MTP` — только `0x1001/0x1014/0x1015` (уже проверено координатором, разрешено).
4. **Дальше нужен владелец:** через `ask` координатору попроси перевести камеру в «USB RAW CONV./BACKUP RESTORE» и переподключить USB. Перед первой отправкой операции скачивания BACKUP — отдельный `ask` с точным опкодом, параметрами и доказательством, что это чтение. После одобрения сними базовый снимок `01_база` (свойства + BACKUP).
5. Затем — серия снимков по сценариям; каждую конфигурацию владелец выставляет руками, ты просишь через `ask` и ждёшь подтверждения:
   - `02_CH_ES_8000_CONT`: DRIVE = CH HIGH SPEED BURST, SHUTTER TYPE = ELECTRONIC (и отдельно MECHANICAL+ELECTRONIC), выдержка 1/8000 (и короче, если есть), IMAGE DISP = CONTINUOUS;
   - контроли — по одному отличию от сценария: `03_S` (DRIVE = S), `04_MS` (механический затвор), `05_1-250` (выдержка 1/250), `06_DISP_OFF` (IMAGE DISP = OFF);
   - `07_база_повтор` — вернуть как в `01_база`, для контроля шума.
6. **Сравнение:** скрипт `diff_snapshots.py` — какие свойства и какие байты BACKUP-блоба меняются между снимками; отдельно — какие изменения уникальны для сценария `02` относительно всех контролей.

## Результат

`отчёт.md` (операции и их обоснование «только чтение», что сделано, таблица изменений по снимкам, кандидаты на поле флага), сами снимки и скрипты. В worker_done — какие опкоды использованы, где лежат снимки и что меняется уникально в сценарии CH/ES/1-8000/CONTINUOUS. Если BACKUP недоступен/небезопасен — сделай серию только на свойствах и зафиксируй это.
