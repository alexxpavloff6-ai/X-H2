## Камера (проверено координатором, только чтение)

- X-H2, **прошивка 5.30** (`WPD_DEVICE_FIRMWARE_VERSION = 5.30`, `DeviceVersion "5.30"`), USB `VID_04CB&PID_02F2`, драйвер WPD/MTP.
- Сейчас режим передачи файлов (MTP, `FunctionalMode 0`): 24 операции `0x1001–0x100B, 0x100E, 0x1014–0x1018, 0x101C, 0x900C, 0x900D, 0x901D, 0x100C, 0x100D, 0x9018`; значения свойств в этом режиме камера не отдаёт.
- Свойства (профили проявки, D-коды) камера отдаёт только в режиме «Настройка соединения → Режим подключения к ПК → **USB RAW CONV./BACKUP RESTORE**» (так работало 10.11.2026). Переключает режим **только владелец, руками на камере**.
- Лог: `Анализ_прошивки\Камера_2026-11-17\00_DeviceInfo\xh2_ptp_read_log_140757.txt`.

## Цель

Связать guard-флаг исправления LCD-линий с реальным режимом камеры. Из статики известно (адреса **5.30**!):
- флаг MOVDC = глобал `0x4c33f14` (в 5.33 `0x4c2ff14`) = копия `params.current+0x74`; current = `0x4C3F1F8`, pending = `0x4C3F090` (в 5.33 `0x4C3B1F8/0x4C3B090`);
- params заполняются чтением **записи настроек id `0x4C`** (`get_record`, геттер `0x14C6384` в блоке 0 — адрес 5.33, для 5.30 пересчитать), хранилище записей — за сервисным RPC (диспетчер `0x4A458`, блок 2);
- в 5.30 **нет** исправления (guard), т.е. дефект должен воспроизводиться: DRIVE = CH HIGH SPEED BURST, SHUTTER TYPE = MECHANICAL+ELECTRONIC при фактическом электронном затворе, выдержка 1/8000 и короче, IMAGE DISP = CONTINUOUS.
- id-пространства не путать: record-id (`0x4C`), `UI_SETP`-номер (= id свойства камеры), state-bit API.

## ПРАВИЛА БЕЗОПАСНОСТИ КАМЕРЫ (обязательны)

1. С камерой работает **только один исполнитель за раз** (K1). Остальные — только файлы.
2. **Только чтение.** Разрешены: `0x1001` GetDeviceInfo, `0x1014` GetDevicePropDesc, `0x1015` GetDevicePropValue и (после обоснования и одобрения координатором) операции **скачивания** резервной копии настроек камера→ПК.
3. **Запрещено** без отдельного разрешения владельца через координатора: `0x1016` SetDevicePropValue, `0x100C/0x100D` SendObject*, `0x100B` Delete, `0x100F` Format, `0x100E` InitiateCapture, восстановление настроек (RESTORE), любые вендорские `0x9xxx`, пока не доказано, что они только читают; сервисный/отладочный режим, чтение/запись RAM через отладочный канал fujimod, перезапуск, обновление прошивки, изменение драйверов Windows.
4. Не менять настройки камеры программно — их меняет владелец руками; исполнитель просит об этом координатора (`ask`).
5. Каждая новая операция: сначала документальное обоснование «только чтение» (ссылки на fujimod/fujicli/наши логи), затем `ask` координатору с точным опкодом и направлением данных, только после ответа — отправка. Белый список в коде, всё прочее — отказ.
6. Не перезаписывать существующие логи; результаты — в `Анализ_прошивки\Камера_2026-11-17\<папка_задачи>\`.
