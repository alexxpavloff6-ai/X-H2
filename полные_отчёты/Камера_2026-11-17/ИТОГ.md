# Итог: исследование на подключённой камере X-H2 (17.11.2026)

Координатор — Claude Opus 5.5. Исполнители — Kimi K3.1 Pro (K1, K2; остановлены по лимиту) и Qwen 4 Max, effort max (Q1, Q2, Q3).
Камера X-H2 с прошивкой **5.30** (исправления LCD из 5.33 в ней нет). Режим USB «USB RAW CONV./BACKUP RESTORE».
Уровни: **Д** — доказано (код/VM/данные камеры), **К** — сильный кандидат, **Г** — гипотеза.

## Безопасность работы с камерой

17 снимков (12 в основной серии и 5 в серии порога), отправлены **только операции чтения**: `0x1001` GetDeviceInfo, `0x1014/0x1015` чтение свойств и, с разрешения владельца, `0x1008/0x1009` (GetObjectInfo/GetObject, handle 0) — скачивание резервной копии настроек, ровно по одному разу на снимок. Ни одной операции записи, восстановления, сервисного/отладочного режима. Инструмент с жёстким белым списком: `K1_камера\xh2_snapshot.py`. Журналы каждого снимка проверены координатором.

## Главный результат: условие LCD-исправления замкнуто от настроек камеры до флага (Д)

Guard-флаг исправления горизонтальных линий на LCD (флаг MOVDC `0x4C33F14` в 5.30 = поле `+0x64` сервисной записи `0x4C`) вычисляет предикат `0x2FE35D4` → оценщик `0x30256EC` → `0x30308A0` по таблице `0x3456B20`; результат кладёт построитель параметров `0x2FE38E4` в `[sp+0x120]+0x64`, запись `0x4C` пишется через API `0x14CF124` (86 вызовов с id `0x4C`). Сервисный модуль записей — загрузчик DAT `0x60274 → VA 0x40000` (а не блок 2).

Оригинальный код прошивки 5.30 исполнен в Unicorn на входах из **реальных резервных копий** камеры (`Q3_мост\43_vm_конфигурации.py`, перепроверено координатором):

| Снимок | Фактический затвор | CH + CONTINUOUS | Выдержка | Флаг |
|---|---|---|---|---|
| 01 база | EF | нет | 1/25 | 0 |
| 02 | EF | да | 1/8000 | 0 |
| **02B** | **ES** (MS+ES→ES) | **да** | **1/16000** | **1** |
| **02C** | **ES** | **да** | **1/8000** | **1** |
| 03_S | ES | нет (S) | 1/8000 | 0 |
| 04_MS / 04_MS_CH | MS | нет / да | 1/8000 | 0 |
| 05 | ES | да | 1/250 | 0 |
| 06 | ES | нет (OFF) | 1/8000 | 0 |

Флаг = 1 **только** в сценарии дефекта по описанию Fujifilm (CH + фактически электронный затвор + быстрая выдержка + IMAGE DISP CONTINUOUS). **К:** как камера строит гейт «CH + CONTINUOUS» (`fieldA`, писатель `struct+0xCC`) — выведено из снимков, код писателя не прослежен. **Новое:** по таблице флаг включается уже при выдержке **≤1/600** (вход = знаменатель/100 ≥ 6), т.е. шире заявленного Fujifilm «1/8000 и короче»; промежуточные выдержки на камере не проверялись.

## Серия порога (снимки 08–11) и визуальная проверка дефекта

Q3 записал предсказание по кодировщику выдержки `0x14F396C` и таблице `0x3456B20` **до** снимков: вход = знаменатель/100, флаг = 1 при ES и входе ≥ 6, т.е. граница между 1/500 и 1/640. Снимки CH + ES + M + CONTINUOUS (Д, VM на реальных входах, совпало 4/4):

| Снимок | Выдержка | Флаг (VM) | Видимые линии на LCD (наблюдение владельца) |
|---|---|---|---|
| 08 (EF — промах конфигурации, контроль) | 1/500 | 0 | нет |
| 08B | 1/500 | 0 | нет |
| 09 | 1/640 | **1** | нет |
| 10 | 1/1000 | **1** | нет |
| 11 | 1/4000 | **1** | нет |
| (без снимка) ES | 1/8000 | 1 (как 02C) | нет |
| (без снимка) MS+ES | 1/16000 | 1 (как 02B) | нет |

Выводы:
- **Порог флага прошивки ≈ 1/600** (граница 1/500 → 1/640) — **Д**; это шире, чем «1/8000 и короче» в описании Fujifilm.
- **Флаг ≠ видимый дефект.** На этом экземпляре X-H2 5.30 горизонтальные линии **не наблюдались ни на одной** проверенной выдержке, включая ровно сценарий Fujifilm (1/8000 ES и 1/16000 MS+ES, CH, CONTINUOUS, длинные серии). Fujifilm формулирует дефект как возможный («могут появиться»), т.е. он проявляется не всегда; флаг — условие режима, в котором 5.33 включает защиту (stride из геометрии), с запасом.
- Для 02B/02C в первой серии визуальная проверка не проводилась; утверждение «полосы воспроизведены на 02B/02C» в промежуточном отчёте Q3 было ошибочным и исправляется.

## Резервная копия настроек (`FUJIFILM X-BACKUP0100`, 70 524 байта)

- Карта откалибрована по реальным снимкам (`K2_прошивка\decode_backup.py`, `карта_банка.*`), все изменения в парных сравнениях объяснены. Поля: тип затвора `0x63A` (0 MS, 1 ES, 2 MS+ES, 3 EF), фактический затвор `0x1A8`, серия `0x4F8`/`0x68C` (21 = CH), выдержка `0x18C` (знаменатель×100), IMAGE DISP `0x29B` (2 CONTINUOUS, 3 OFF).
- **Guard-флага и записи `0x4C` в копии нет** (Д): флаг не сохраняемая настройка, а вычисление во время работы.
- **«Выходные» поля** (`0x1A8`, `0x1D8`, `0x18C`, `0x681`) и `0xF6BC` обновляются **при перезапуске питания**, а не при выборе в меню и не при спуске (Д: снимки 07/07B без перезапуска — устаревшие, 07C после перезапуска — совпал с базой). `0xF6BC` растёт на каждом перезапуске — не счётчик спусков (назначение не установлено).
- `FRONT_CMD_ASSIGN` менялся без участия владельца (1154→20→1154) — контекстное состояние интерфейса (меню/экран съёмки), не настройка (Г).
- Q2 (матрица 12 снимков, `K2_прошивка\10_матрица.py`): условие дефекта по копии = конъюнкция четырёх полей; выполняется только в 02B и 02C. Каждый из четырёх факторов изолирован чистым контролем с одним отличием (02C↔03_S — серия, 02C↔04_MS_CH — тип затвора, 02C↔05 — выдержка, 02C↔06 — IMAGE DISP). 07/07B помечены как снимки с устаревшими «выходными» полями.

## Поправки по ходу

- В снимках 01/02 тип затвора был **EF**, а не ES (координатор ошибочно сказал «ES уже стоит» по первой карте) → 02 не сценарий дефекта; добавлен чистый 02C.
- 04_MS фактически S+MS (DRIVE остался от 03) — оставлен контролем, снят 04_MS_CH.
- Q3 в 1-м круге ошибочно заключил «кода нет» — мост найден во 2-м круге после верного определения сервисного модуля.
