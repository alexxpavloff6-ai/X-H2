X100VI 1.31: исследование цепочки четырёх цветовых коэффициентов

Источник: Firmware на прочиеFuji/FPUPDATE.DAT, SHA-256 0d48d2ae26ac7ebab9b0e4cac56324807ec1ea8ae30df06b0b9e79066dc0a14a. DAT открывался только для чтения; совпадение контрольной суммы до и после проверено программой. Камера не использовалась.

ГЛАВНЫЙ ВЫВОД И ВАЖНАЯ ОГОВОРКА

В коде X100VI исполнены связанные через переданные программой результаты отдельные этапы от кода интерфейса Classic Chrome до четырёх вычисленных чисел, их упаковки и двух записей в виртуальную память по адресам устройства. В словарях UI код 14 обозначен UI_FILM_SIM_CLASSIC_CHROME; исходная функция X100VI 0x013C9930 при аргументах [1756,14,0,3] вернула режим 13 без ошибки, а функция цветового блока преобразовала его в 8. Исходный пользовательский ввод и работу камеры опыт не наблюдает. Внутренние значения 0…8 пока не привязаны к отображаемым положениям X100VI; название «Цвет» для преобразуемой настройки основано на методике X-H2, а не на полном прослеживании меню X100VI.

Все адреса машинных функций ниже получены из заголовков распакованных блоков X100VI, а не скопированы из X-H2. Это адреса образа в эксперименте, не смещения в сжатом DAT и не наблюдение RAM камеры. Блоки FFLZ начинаются в DAT по 0x9C02BC и 0x10E02BC, базы распакованных блоков 0x011C1000 и 0x02B8F000. Виртуальные диапазоны блоков перекрываются; в эксперименте сначала записан первый блок, затем второй. Моделируемый низкоуровневый код записи взят из инвертированных байтов DAT по 0xDE01C; исходный BL вызывает адрес 0x0009ED60, куда он и отображён. Это настоящие команды STR w1, [x0]; RET. Использована не камера, а виртуальная память.

НАБЛЮДАЕМАЯ ЦЕПОЧКА

1. Функция 0x013C9930 с аргументами [1756,14,0,3] вернула 13; заранее обнулённый флаг ошибки 0x020B44C4 после вызова равен 0. В словаре UI значение 14 соответствует UI_FILM_SIM_CLASSIC_CHROME. Результат 13 передан вызываемой отдельно функции 0x0314EEE4, которая записала код цветового блока 8. Программа отдельно выполняет её для входов 0…23 и сохраняет результаты. Весь переход воспроизведён на искусственных параметрах, не на событийной цепи настоящей камеры.
2. При параметрах +0x12C=1, +0x130=8 и остальных полях, указанным в программе, функция 0x0313A1C0 выбрала селектор 6. Она читает из образа настроек байт по ключу 0xB12D, равный 6. Последующее выполнение подготовки вызывается на той же искусственной структуре.
3. Таблица ключей 0x0365F538 в распакованном втором блоке; шестая запись (смещение 5*16) — 0xB058, 0xB05A, 0xB05C, 0xB05E. Эти адреса являются смещениями в исходном инвертированном образе настроек, начало которого в DAT 0x6602BC. По DAT 0x66B314…0x66B31A лежат u16: 885, 859, 8182, 8180. Интерпретация последних как знаковых 13-битных значений даёт −10, −12. Порядок исходного набора a,d,b,c. Это базовый образ обновления, не индивидуальная калибровка камеры.
4. Функция 0x0314F388 с входом native=0…8 и дополнительными аргументами 1,0 дала индекс 8…0. Вход 1,0 — искусственные условия. Функция 0x0313CEF8, включая 0x0313CE80 и 0x0313A590, сформировала четыре signed16 в +0x1DA…+0x1E0. При остальных заданных в скрипте значениях множители, помимо соответствующего индексу g, равны 128 и 64; каждое число получилось (исходное*g*128*64) арифметически сдвинуто вправо на 20, для отрицательных чисел — округление к минус бесконечности. Это отдельно проверено независимым целочисленным расчётом всех девяти результатов. Порядок выхода a,b,d,c.
5. На тех же выходных данных отдельно вызвана функция упаковки 0x0145FB28. Она ограничивает значения диапазоном −4096…4095, пишет младшие 13 бит в поля +0x1EC…+0x1F2, сохраняя три старших бита каждого. Шесть дополнительных опытов проверили граничные значения −4097, −4096, 4095, 4096 и сохранение старших бит 0, 0xA000, 0xE000. Основные девять опытов использовали исходно нулевые поля образа.
6. Затем отдельно вызвана функция передачи 0x0145FBDC с полученным образом. Она использует две записи таблицы по 0x019DCA28: назначения 0xFF96C634 и 0xFF96C638, источник +0x1EC и +0x1F0, по одному 32-битному слову. Функция 0x0145C1DC вызывает низкоуровневую запись 0x0009ED60. Перехват наблюдал обе 32-битные записи в виртуальной памяти. Между этапами данные переданы исследовательской программой; автоматический вызов этой функции в полном цикле съёмки, маски обновления и условия его запуска не доказаны.

ГРАНИЦЫ И ВОСПРОИЗВЕДЕНИЕ

Реальное состояние меню и EEPROM камеры, привязка значений к именам элементов X100VI, аппаратная обработка пикселей и полный RAW→JPEG не наблюдались. Тесты показывают указанный программный путь при сконструированных условиях, не обязательность его вызова при каждой съёмке. Таблица и данные устройства при иных настройках и калибровке могут отличаться. Запись по адресу в Unicorn не доказывает состояние физических регистров. Никаких изменений или установки прошивки не производилось.

Из корня проекта: python -X utf8 Анализ_прошивки/Единый_глубокий_анализ/X100VI/Цвет/исследовать.py. Нужны Python 3, Unicorn и существующий модуль Анализ_прошивки/анализ_файла.py с его зависимостями. Скрипт создаёт только Результаты.json и Цвет.tsv в своём каталоге; исходные и распакованные образы на диск не пишет. JSON включает карту входных кодов, результаты девяти полных по отдельности вызванных этапов и шесть пограничных испытаний упаковки; TSV — девять строк. Исследовательские исполнения проведены, сборки и наборы тестов не запускались.
