# X-H2S 7.30: единый глубокий разбор

## Исходный файл и метод

Объект — `Firmware на прочиеFuji/FWUP0027.DAT`, SHA-256 **87c566c1ff6343e4c7463a4ef968183f41d1f24cc63d610433d3a387b13f731b**. Файл только читается; повторный хеш после исследования совпал. Байты XOR FF и декодирование FFLZ выполняются в памяти. Заголовки двух распакованных блоков дают модельные базы `0x01421000` и `0x02CCA000`; системный блок из DAT `0x60274` помещён по `0x40000`. Это адресная модель содержимого, не измерение действительной карты памяти включённой камеры. Адреса Linux ELF относятся к его собственному образу.

Сценарий выполнил **274 отдельных запуска исходных фрагментов AArch64 в Unicorn**, не модифицируя инструкции. RAM, регистры, часть исходных аргументов и адресное пространство устройства искусственные; раздельные фрагменты не являются полной загрузкой или непрерывной трассой камеры. Где состояние переносится вручную, это оговорено. Таблицы, полный набор входов и результатов, неподтверждённые кандидаты — в `Результаты.json`; строки подготовленных дескрипторов — в `Задачи.tsv`. Слово «выполнено» ниже означает исполнение в такой VM, не наблюдение устройства.

## 1. Регистрация ThreadX и распределение

**Уровень: локальная подготовка выполнена в VM; вызовы и политика частично статические.** Найдены 111 непосредственных `BL` к регистрационному коду `0x017EDB98`. Ограниченное распространение констант разрешило имена для 106 вызовов; для **105** исходные инструкции заполнения описателя исполнены до соответствующего вызова. Для остальных не хватает разрешённого имени либо адреса входа; они сохранены среди кандидатов, а не объявлены задачами. Кроме того, исполнены концы двух групповых фабрик `0x0318A314` и `0x031AE688` для **25** случаев с константными аргументами вызывающего кода. Получено 130 записей, 129 различных ID; одинаковые ID не следует автоматически считать двумя потоками. Наименование, приоритет, стек, вход, аргумент и место вызова — в TSV. Аргументы на границе подготовительного участка восстановлены ограниченным статическим анализом, а не получены от запущенной камеры.

Для реально полученного дескриптора `md_Monitor` выполнены фрагменты `0x017EDC50..0x017EDC6C` и `0x0004CD74..0x0004CDAC`: адрес входа и аргумент перенесены в нижний дескриптор и в смещения TCB `+0x178`, `+0x170`. Между двумя запусками нижний дескриптор вручную перенесён в искусственную память. Само создание и планирование ThreadX не исполнялось; это свидетельство формата передачи, не список потоков, реально запущенных одновременно.

По адресу `0x01DE5548` найдена таблица, побайтно совпадающая с исследованной таблицей политики X-H2, по записи на ID 1..213. Её значения показаны в колонке `default_policy_candidate`: для 130 записей значения 0/1/2/3/4 встречаются соответственно 60/28/1/40/1 раз. **[ВЫВОД ПО АНАЛОГИИ]** Это кандидат на начальную политику распределения; модельную цепь чтения и изменение политики каждого потока в этом исследовании не исполнили, поэтому числа не следует трактовать как измеренные ядра. Отдельно для задачи Linux есть собственный проверенный фрагмент с маской ниже.

## 2. Диспетчер системной очереди

**Уровень: выполнено в VM до границы вызовов.** В `0x00055FBC..0x00055FDC` поданы искусственные callback `0x12345678` и аргумент `42`. Исходный код сформировал два 32-битных слова `[0x12345678, 42]`, адрес очереди `0x62890`, аргумент ожидания 0. В `0x00055F98..0x00055FA4` в стек вручную подставлен результат успешного получения тех же слов: подготовлены `x0=42`, `x1=0x12345678`. Служба очереди и сам указанный callback не вызваны. Это конкретный механизм передачи, не доказательство, что все настройки или AF пользуются именно им.

## 3. Linux, переход и RPmsg

**Уровень: подготовка дескриптора и аргументов выполнена в VM; загрузка ядра и обмен не выполнялись.** В `0x031F24C0..0x031F2508` построен дескриптор задачи `linux`: ID 192, вход `0x031F2420`, приоритет 10, стек 4096, аргумент 1. Следующий статический вызов `0x031F2520` получает ID `0xC0`, маску `4`; нижний фрагмент `0x00056BC8..0x00056BD4`, исполненный с маской 4, выдаёт маску исключения `0xB`. Это соответствует выбору слота 2 в четырёхбитной модели, но не измерению топологии работающего устройства.

Вход Linux статически обращается к обёртке `0x034A92FC` по `0x031F2470`. Код `0x034A9178..0x034A918C` в VM подготовил `x0=0x07010000`, `x1=x2=x3=0`, `x4=0x07080000`; перед `BLR x4` исполнение остановлено. Фактический переход в Linux, изменение привилегий и загрузка дерева устройств не воспроизводились.

Разобран собственный gzip/newc образ из DAT `0x42DFDCC`, его SHA-256 `c6431b053d338b72bb59cf057f1a2439607c8038cf83119e762c00b45bfa457a`. В `etc/inittab` указаны `rpmsg-daemon` и `ffsys-init.sh`; `etc/rpmsg-daemon.conf` задаёт `/dev/rpmsg_ctrl0`, source 10000, destination 20000. Название `rpmsg-socket-api-channel` найдено в модельном блоке по `0x037569E8` и в самом демоне. Это статические содержимое и конфигурация, не доказательство поднятого канала.

Для **собственного ELF демона из этого CPIO** выполнено `0x0040C3A8..0x0040C3C8` с тремя словами запроса `[2,1,6]`; получены аргументы `socket(2,1,6)`, затем остановка перед `socket@plt` `0x403160`. Системный вызов и сеть не выполнялись. Совпадение строк канала и конкретный разбор запроса не доказывают живой обмен всех задач с Linux.

## 4. Classic Chrome, Цвет, упаковка и виртуальные регистры

**Уровень: несколько модельных фрагментов выполнены в VM; данные между ними передаются искусственно.** Словарь по `0x03538F78` связывает имя `UI_FILM_SIM_CLASSIC_CHROME` по `0x034DAE48` со значением 14. Функция `0x01604DA0`, входы `(1677,14,0,3)`, возвратила 13 и нулевой флаг по `0x0236B408`; запись таблицы `0x01A784C8` содержит `(15,10,13,11)`. Функция `0x0324F9A8` преобразовала 13 в 8. Функция селектора `0x0323B004` с этим значением и описанным в JSON искусственным нейтральным контекстом выбрала 6. Функция `0x0323B400` рассчитала четыре слова **`[866, -27, 996, 69]`**.

В таблице ключей `0x03766458`, строка селектора 6, содержатся смещения шаблона `0xAED8, 0xAEDA, 0xAEDC, 0xAEDE`. Встроенный XOR-шаблон начинается в DAT по `0xC0274`, четыре его u16 — `[866,996,8165,69]`; 8165 в 13-битном знаковом представлении равно −27. Порядок слов выходного блока отличается от порядка исходных ключей. Для сравнения с ранее исполненным X-H2: в аналогичном нейтральном контексте были `[885,-10,859,-12]`; это различие конкретных встроенных значений, а не измерение JPEG или общей цветопередачи камер.

Функция `0x0324FE34` при тестовых входах `(native,1,0)`, native 0..8, дала индексы 8..0. В каждом случае исходный вычислитель повторно исполнен при соответствующем индексе. Например, индекс 4: коэффициент шкалы 128 и слова `[866,-27,996,69]`; индекс 6: 141 и `[953,-30,1097,76]`. Все девять результатов записаны в JSON. Соответствие этих индексов видимым делениям конкретного меню данной камеры отдельно не доказано; не подменяем его численным названием +2. Дополнительный 3D-селектор `0x0323FFEC` для искусственной структуры `(0,1,8,0)` вернул 0; другие контексты и вся 3D-обработка не исследованы.

Далее исходный сборщик `0x032335BC..0x032335D4` сформировал те же четыре слова в общем буфере `+0xB46` и установил бит `0x80`. Исходная функция `0x03233BB8` вызывает упаковку, включая `0x016953B0`: четыре поля по 13 младших бит, старшие три сохраняются. Вызван исходный передатчик `0x03233BE4`, наблюдалась инструкция записи по `PC=0x0005DE10` в **виртуальные** адреса `0xFF96C634` и `0xFF96C638`. При индексе 4 и нулевых верхних битах записаны `0x1FE50362` и `0x004503E4` соответственно. Выполнены все 9 индексов × 3 варианта старших битов; отрицательный контроль без бита `0x80` не записал эту пару. Похожие дескрипторы найдены по `0x01BFC250` и `0x01BFCB20`.

Это сильная цепь от проверенного конвертера и отдельно поданного контекста до виртуальных регистров; она **не** является непрерывной съёмкой и не показывает, что физический ISP исполнил эти записи, как преобразуются пиксели, или что весь рецепт сводится к четырём коэффициентам.

## 5. Обновление

**Уровень: подготовка четырёх запросов выполнена в VM; вызывающие участки найдены статически.** Исходный синтетический буфер — `44 33 22 11 88 77 66 55 CC BB AA 99 00 FF EE DD`.

| Этап | Статический вызов → начало helper | Выполненный участок до вызова | Команда, байт | Результат payload |
|---|---|---|---|---|
| INIT | `0x02D6AFBC → 0x03052E04` | `0x03052E04..0x03052E3C` | `0x600`, 16 | `443322118877665500FFEEDDCCBBAA99` |
| START | `0x02D6B074 → 0x03052E48` | `0x03052E48..0x03052E64` | `0x602`, 4 | `44332211` |
| WRITE | `0x02D6B154 → 0x03052E70` | `0x03052E88..0x03052E9C` | `0x603`, 4 | `44332211` |
| DEINIT | `0x02D6AE70 → 0x03052EAC` | `0x03052ECC..0x03052EE0` | `0x601`, 4 | `44332211` |

WRITE и DEINIT начинаются после отдельного служебного вызова; для них `x19` искусственно содержит указатель на тестовый буфер. Упаковщик `0x03052DBC` и его вызов транспорта `0x03052DF4 → 0x017EECB8` установлены статически, но во время этих экспериментов транспорт не вызван. Диагностические строки `>> update_init/start/write/deinit()` присутствуют по `0x03548010/28/40` и `0x03547FF8`. Это не полная цепь от чтения карты через проверку подписи до контроллера энергонезависимой памяти; физическая запись, порядок проверок, A/B и восстановление при сбое здесь не доказаны.

## 6. Автофокус и объектив

**Уровень: дескрипторы выполнены, первые обращения подготовлены в VM; назначение вызываемых функций статически не установлено.** Среди зарегистрированных имён найдены `lenscom` вход `0x01708E54`, `lensdata` `0x0170EC5C`, `lensdc` `0x01886390`, `paf` `0x03447C48`, `paf_sub0` `0x034494FC`, `paf_sub1` `0x03449544`, `directaf` `0x0348A108`. Для шести первых исполнено начало функции до первой инструкции `BL`, с нулевым искусственным аргументом и памятью. Например, `paf` достигает `0x03447C6C → 0x03464DEC`; `paf_sub0` доходит до `0x03449530 → 0x017EEEE8` с `x0=0x93`, `paf_sub1` до `0x03449578 → 0x017EEEE8` с `x0=0x94`. Вызванные функции не исполнялись. Остальные прямые `BL` в первых 192 байтах каждой точки — в JSON; некоторые могут принадлежать следующей функции или недостижимой ветви и представлены только статически.

Для `directaf` попытка дойти от входа до первого линейно найденного `BL 0x0348A170` в заданном искусственном состоянии не достигла границы; ошибка сохранена, успешный вызов не заявляется. Сам алгоритм измерения фазы, обнаружение лица, управление мотором, физическая цепь датчик→AF→объектив и распределение вычислений по процессорам не восстановлены. Название `paf` само по себе не доказывает смысл его алгоритма.

## Воспроизведение

Из корня проекта: `python Анализ_прошивки/Единый_глубокий_анализ/X-H2S/исследовать.py`. Нужны Python и поставленные в репозиторий библиотеки Capstone и Unicorn. Скрипт использует существующие декодер FFLZ, анализатор констант и разборщик CPIO; не записывает распакованную прошивку на диск, результаты создаёт только в своём каталоге. `Результаты.json` хранит все исходные параметры и вычисленные наблюдения; `Задачи.tsv` — машинный список подготовленных дескрипторов. Фактическое выполнение отдельных инструкций в VM не означает, что в камере встречается каждый искусственный контекст.
